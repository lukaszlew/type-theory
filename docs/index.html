Types as sets of terms: a technique, and what it reaches

The Narrow Path

These notes are about one technique for understanding a type system. A type expression, such as ∀X. X → X, is read as the name of a set of untyped terms; such a set is called a type set, and it has to satisfy three conditions. A typing rule is then not an axiom but a statement about the named sets, which is true or false, and can be checked. When every rule is true, two theorems follow at once: every typable term is strongly normalizing, so that no way of running it goes on forever, and the system is consistent. That is the first thing the technique gives, and the notes prove it for System F in a few lines. The rest of the notes is about what else the same reading gives, because the sets outlast the proof: an exact account of what each rule costs and which additions are cheap; a verdict on every proposed rule, with the reason when the verdict is no; a meaning for a hypothesis, for an equality, for a term with annotations; and the same theorems again when the reading is run on pairs of terms, on smaller collections of sets, or on larger languages. The narrow path is the definition of a type set: each natural simplification of it fails, and the notes show every failure next to the clause it concerns. Particular systems from the literature appear as tests of the technique, not as its subject.

What this page claims

  1. One definition carries the difficulty. A type set is a set of untyped terms with three conditions (§5). In ∀X. X → X the variable X ranges over all type sets, which are fixed before any type expression exists, and there are far more of them than type expressions can name (§11). The three conditions cannot be weakened in any natural way: each simplification is tried and fails (§6), and the failures are what the theorem demands (§15).
  2. The rules are facts about sets, and the proof uses little. Every type expression names a type set (§10), each rule of System F is one of four facts about sets (§9, §13), and strong normalization and consistency follow in two lines. What the proof uses is listed where it is used: three facts about SN (§16), five about the collection that ∀ ranges over and a short list about terms (§13), and one strong principle, the intersection over all type sets, whose strength §17 measures and §41 shows is paid once.
  3. Adding a rule has a fixed price. The addition lemma (§18) says that a new form of type expression costs one lemma, that its clause gives type sets, and one membership fact per rule; nothing proved before is touched. The price is paid in full once, for intersection types (§19), with which the rules reach every strongly normalizing term (§21), and then in a few lines each for subtyping, least fixed points, existential types, self types, the dependent intersection, the implicit product and equality types; dependent types and higher kinds extend the lemma itself, once each. §23 says exactly where a rule stops being cheap, and why.
  4. Larger languages name members of the same collection. Dependent types (§24 to §26), types that mention the term they type (§27 to §30), inductive types built three ways (§31) and System Fω (§32 to §34) add forms of type expression, and every one of them names a type set of the kind defined in §5. For each rule of each system the page says whether it is true as a statement about sets; where a rule is false, the semantics gives a counterexample, and the reasons are of two kinds only: a set that is not a type set (§14), or a rule that asks a hypothesis to carry a fact about other terms, which a term cannot do (§40).
  5. The one choice in the definition is dissolved, not defended. The three conditions are Tait’s. Girard’s candidates, the head-closed type sets and the sets defined by tests are three smaller collections that satisfy them, and the four form a chain (§35, §36, §37): each is closed under the arrow and under intersections, each carries the theorem, and each asks of a set one more invariance than the one before. The head-closed collection is exactly the sets of values and the only one with complements, which makes the picture “a type set is a set of values” exact.
  6. The same proofs run on other inputs. Run on pairs of terms, the reading makes a type expression name a relation, and gives Reynolds’s abstraction theorem and its free theorems with no new proof (§38). Run on a smaller collection, it gives the other collections’ theorems. What the proofs ask of their inputs is written down once (§13), so that the reader can see what else would carry them.
  7. The reading answers questions that the rules do not ask. What an equality between terms can be, and why none is built in (§7, §39); what a hypothesis means (§40); what a term with annotations needs before the theorem reaches it, as one lemma and an inventory (§42); and what each corner of the λ-cube costs (§43).
  8. The status of every claim is on the page. Each lemma’s header says whether it is textbook, quoted, or worked out here, and whether a reader independent of the author re-derived it; the closing section lists what is quoted, what is the page’s own, what reviews found and fixed, what is open, and what is not here. The sections that treat one particular system are the specialist ones; the goal selector shows what each needs, and none is needed by the main line.

The proof in five lines

  1. Terms are untyped, and strong normalization is a property of terms (§1).
  2. A type set is a set of strongly normalizing terms that contains one fixed set of terms, called Base, and is closed under undoing safe head steps (§2, §5).
  3. Two operations on type sets, the arrow and the intersection over all type sets, give type sets again (§8).
  4. A type expression such as ∀X. X → X names a type set (§10), and each typing rule is a true fact about the named sets (§9, §13).
  5. So a typable term is a member of a type set, and members of type sets are strongly normalizing (§13).

What here is not in the textbooks

The main line is Girard’s proof in Tait’s form, and the page says so. Worked out for the page, and re-derived by readers independent of its author, are: the narrow points, each a counterexample to a simplification of the definition (§6, §11, §14, §34); the addition lemma (§18); the lemma that type sets tell every two terms apart, which is why every equality has to be added (§7); the characterization of Girard’s candidates as the type sets closed under steps, with a two-line proof of Riba’s theorem on unions (§35); the chain of four collections, the correspondence between head-closed type sets and sets of values, and the lemma that only the head-closed type sets have complements (§36, §37); the lemma that every closed term fails some test (§37); the lemma that the main line uses nothing about terms beyond a short list, so that it runs on pairs (§38); the erasure lemma with its inventory (§42); and, among the tests of the technique on particular systems, the verdict that a rule which retypes a term by an equation cannot be true in any semantics that proves strong normalization (§30), and the fit of Mendler-style inductive types, whose fixed point and constructor ask nothing of the signature (§31). Which of these is known elsewhere under another name is said where it is known; the closing section keeps the account.

Part I · Terms

§1Terms and steps

Uses nothing before it. Used by §2.

Definition · Terms and reduction

A term is one of three things:

x
a variable;
λx.t
an abstraction, where t is a term;
t u
an application, where t and u are terms.

In short:

t, u ::= x | λx.t | t u

Application groups to the left, so t u v means (t u) v.

A subterm of a term is the term itself or any term that occurs inside it.

A variable x is free in a term if it occurs there outside every λx.

A term is closed if no variable is free in it. For example λx.x is closed, and λx.x y is not.

The substitution t[u/x] is the term t with a copy of u in place of every free occurrence of x.

Terms that differ only in the names of bound variables count as the same term. Substitution renames bound variables if needed, so that no free variable of u becomes bound.

The simultaneous substitution t[u1/x1,…,un/xn] replaces all of the variables x1,…,xn at once.

A redex is a term of the form (λx.t) u.

There is one rewrite rule, called β. It rewrites a redex:

(λx.t) u → t[u/x]

A step, in full a β-reduction step, applies β to one redex. The redex may be any subterm:

if t → t′ then λx.t → λx.t′, t u → t′ u and u t → u t′

A run, or reduction sequence, is a sequence of steps.

To run a term is to take steps from it.

A normal form is a term that has no step.

Two modeling choices are made here. The terms are untyped: type sets do not exist yet, §5 defines them as sets of these terms, so the terms come first and carry no annotations. And β is the only rewrite rule. The usual second rule, η, which rewrites λx.t x to t when x is not free in t, is left out. The price is paid later: λx.K x and K are different terms that no step joins (§7), and a statement that two functions with the same results are equal has no home on this page (§39). The reason is cost: with η, the forms of terms in §2 and the conditions of §5 would have to be restated for one more sort of step, which is the work that limit 4 of §23 describes.

Example · What a step does to its argument

It depends on how often the variable occurs.

  • Once: (λx.x) u → u. The argument is moved.
  • Twice: (λx.x x) u → u u. The argument is copied, and the term can grow.
  • Not at all: (λx.y) u → y. The argument is discarded, and whatever it would have done never happens.

Copying is what makes strong normalization hard to prove. If no abstraction used its variable more than once, every step would make the term shorter, and no term could run forever. With copying, no simple measure of size goes down. Discarding is what makes the order of steps matter.

Definition · Strongly normalizing

A term is strongly normalizing if no infinite run starts from it. Every way of running it stops, whatever order the steps are taken in.

SN is the set of strongly normalizing terms. So t ∈ SN says that t is strongly normalizing.

A term is weakly normalizing if at least one run from it ends in a normal form.

This page does not say that a term “terminates”. That word does not say whether one run stops or every run does.

Four terms are used as examples throughout.

NameTermWhat it does
Iλx.xreturns its argument
Kλx.λy.xkeeps the first argument, discards the second
δλx.x xcopies its argument and applies it to itself
Ωδ δδ applied to itself

Example · Normal forms

I, K, δ and y y are normal forms. No step is possible, so they are strongly normalizing. A term with one step and then none, such as I I → I, is strongly normalizing too.

Example · A loop

Ω = (λx.x x) δ → δ δ = Ω. Its only step copies δ and rebuilds the same term. It is not even weakly normalizing.

Example · A term with several runs

Take δ (I y), where y is a variable. Two steps are possible at the start: the outer one, which copies the argument, and the inner one, I y → y. That gives three runs that go on until no step is left.

δ (I y) → δ y → y y
δ (I y) → (I y) (I y) → y (I y) → y y
δ (I y) → (I y) (I y) → (I y) y → y y

Every run stops, so the term is strongly normalizing. The runs that copy first are longer, because the copied redex has to be reduced twice.

Example · Weakly but not strongly normalizing

K I Ω can stop: K I Ω → (λy.I) Ω → I, where the last step discards Ω. It can also step inside Ω forever. So it is weakly normalizing and not strongly normalizing. The definition of SN asks about every order of steps, and one finishing run is not enough.

§2Head steps

Uses §1 Terms and steps. Used by §3, §4.

One sort of step gets a name of its own, because the definition of a type set in §5 is stated with it.

Definition · Head step

Every term has exactly one of three forms, with n ≥ 0:

λx.t
an abstraction, for example λx.x x;
x u1…un
a variable applied to arguments, for example y and y δ δ;
(λx.t) u u1…un
an abstraction applied to arguments, for example I I and K K y.

The head step of an abstraction applied to arguments reduces the redex at its front:

(λx.t) u u1…un →h t[u/x] u1…un

The argument of this head step is the term u.

A head step is safe if its argument is in SN.

An abstraction has no head step, and a variable applied to arguments has no head step.

Repeating head steps is called weak head reduction.

A head step survives one more argument: if s →h s′, then s v →h s′ v, with the same argument. §8 uses this.

Example · Head steps

  • K K y →h (λb.K) y →h K. Both head steps are safe: their arguments are K and y.
  • (λx.y) Ω →h y. This head step is not safe, because its argument is Ω.
  • λx.K x has a step, to λx.λb.x, and no head step. y (I I) also has a step and no head step.

Lemma R · Three facts about stepstextbook

R1
Subterms. If t ∈ SN, then every subterm of t is in SN, and every term that t steps to is in SN.
R2
Variable applied. x u1…un ∈ SN if and only if u1,…,un ∈ SN.
R3
Safe head step. If s →h s′ is safe and s′ ∈ SN, then s ∈ SN. Written out: if t[u/x] u1…un ∈ SN and u ∈ SN, then (λx.t) u u1…un ∈ SN.

R3 (safe head step) says that strong normalization survives undoing a safe head step. The word “safe” matters: if x is not free in t, the head step throws u away, and then nothing is known about u.

These three facts are all that the main proof uses about strong normalization.

Proof

R1. A step inside a subterm of t is a step of t. A run from a term that t steps to is the tail of a run from t.

R2. No step can change the variable that is applied, so the term stays a variable applied to arguments. Every step happens inside one of the arguments.

R3. Write s for the term before the head step and s′ for the term after it. The subterms t, u, u1,…,un are all in SN: u by assumption, each ui as a subterm of s′, and t because every step of t is also a step of t[u/x], which is a subterm of s′.

Take any sequence of steps from s. As long as the head step is not taken, each step is inside one of these subterms, and those stop. If the head step is taken, the result is a term that s′ can reach by steps, and s′ ∈ SN. Either way the sequence is finite. ∎

Example · R2 at work

y δ δ ∈ SN by R2 (variable applied), because each argument is in SN. Nothing ever applies the first δ to the second: the variable y stands in the way.

Example · R3 at work, and why it asks for a safe head step

(λx.y) (I I) ∈ SN by R3 (safe head step). Its head step leads to y, which is in SN, and the head step is safe because its argument I I is in SN.

(λx.y) Ω also has a head step to y. That head step is not safe, because its argument Ω is not in SN. And the whole term is not in SN: Ω can be run inside it forever.

§3SN is generated by three rules

Uses §2 Head steps. Used by §16, §21.

SN was defined by what its members cannot do: they have no infinite run. It can also be built up, by three rules.

Generation lemma · SN is generated by three rulesquoted

Let S be a set of terms that is closed under these three rules:

variable applied
If u1,…,un ∈ S, then x u1…un ∈ S, for every variable x and every n ≥ 0.
abstraction
If t ∈ S, then λx.t ∈ S.
head step
If s →h s′, and s′ ∈ S, and the argument of the head step is in S, then s ∈ S.

Then SN ⊆ S.

SN is itself closed under the three rules. So SN is the smallest set that is closed under them.

Proof

SN is closed under the three rules. Variable applied is R2 (variable applied). Abstraction: every step of λx.t is a step inside t, so an infinite run from λx.t would give one from t. Head step is R3 (safe head step).

SN ⊆ S. Suppose that some t0 ∈ SN is not in S. By §2 it has one of three forms.

  • If t0 is x u1…un, then some ui is not in S, by the rule variable applied.
  • If t0 is λx.t, then t is not in S, by the rule abstraction.
  • If t0 is (λx.t) u u1…un, then u is not in S, or the term after the head step is not in S, by the rule head step.

In each case there is a term t1 that is not in S, and that is either a proper subterm of t0 or a term that t0 steps to. By R1 (subterms), t1 ∈ SN. The same argument applies to t1, and so on. This gives an infinite sequence t0, t1, t2, … in which each term is a proper subterm of the term before it, or a term that the term before it steps to.

A proper subterm is smaller, so the sequence takes a step infinitely often. Now follow the sequence inside t0. If the sequence moves to a proper subterm, then the term around it stays as it is. If the sequence takes a step, then the term around it takes the same step, because a step of a subterm is a step of the whole term. So t0 takes infinitely many steps, and that contradicts t0 ∈ SN. ∎

The lemma is a known fact, due to van Raamsdonk and Severi. The proof given here is this page’s, and it was re-derived by an independent reader. The soundness theorem does not need the lemma. §16 and §21 use it.

Part II · Type sets

§4The obstacle

Uses §2 Head steps. Used by §5.

The plan is to show that terms built in approved ways are strongly normalizing. The obvious method is to check that each way of building a term keeps the property “strongly normalizing”. Application already breaks this.

Narrow point 1 · One set is not enough

Goal
Show that terms built in approved ways are strongly normalizing.
Try
Prove “strongly normalizing” directly, by showing that it passes from the subterms of a term to the term itself.
Breaks
δ ∈ SN. δ δ = Ω does not. Applying one strongly normalizing term to another can loop.
Hence
Use a stronger property that says what a term does when it is applied. One such property cannot fit all terms: I may be applied to any strongly normalizing term, and δ may not. So there have to be many properties, that is, many sets of terms, and a way to say that applying a member of one set to a member of another lands in a third.

The way to say it is the arrow.

Definition · The arrow

For sets T and U of terms, the arrow T ⇒ U is the set of terms that send every member of T into U:

T ⇒ U = { t : t u ∈ U for every u ∈ T }

Example · SN ⇒ SN

SN ⇒ SN is the set of terms that send every strongly normalizing term to a strongly normalizing term. I is in it: if u ∈ SN, then I u ∈ SN, by R3 (safe head step). δ is not in it, because δ ∈ SN and δ δ ∉ SN. It is inside SN: if t is in it, then t y ∈ SN for a variable y, so t ∈ SN, as a subterm. So SN ⇒ SN is strictly inside SN, and it is a property of the stronger sort that narrow point 1 asks for.

The sets that the proof works with will be called type sets. §5 defines them. Here first is how the proof will go, and what it needs from them.

A term is built from variables by application and by abstraction, and the proof follows that. It shows that each typable term belongs to a type set. For an application it uses the definition of the arrow: if t ∈ T ⇒ U and u ∈ T, then t u ∈ U. That costs nothing. For an abstraction it needs a way into T ⇒ U (W3). For ∀ it intersects type sets, and the result has to be a type set again (W4), as the arrow of two type sets has to be (W2). At the end, membership has to give strong normalization (W1). A term with free variables, such as x y, is handled by replacing x and y by members of type sets. To get a statement about x y itself, they are replaced by themselves (W5).

The soundness theorem of §13 and its first corollary, that every typable term is strongly normalizing, need nothing else from type sets. The second corollary, consistency, also needs that the smallest type set has no closed member.

Requirements

W1
Inside SN. Every member of a type set is strongly normalizing.
W2
Arrow. If T and U are type sets, then so is T ⇒ U.
W3
Abstraction. If T and U are type sets and t[u/x] ∈ U for every u ∈ T, then λx.t ∈ T ⇒ U. This is how abstractions get into T ⇒ U.
W4
Intersection. The intersection of any nonempty collection of type sets is a type set. §8 needs this for ∀.
W5
Variables. Every type set contains every variable. The proof ends by replacing each variable by itself, in §13, and for that they have to be members.

§5 gives a definition that meets all five. §6 shows that the simpler definitions it tries do not.

§5Type sets

Uses §2 Head steps, §4 The obstacle. Used by §6, §7, §8.

In everyday use the word “type” covers two things. This page keeps them apart and never uses the word alone. A type expression is something one writes, such as X → X. Type expressions arrive only in §10. A type set is a set of terms that satisfies the three conditions of the definition. The bare word is left only inside a few standard names, such as “dependent types”.

Definition · Type set

Write Base for the set of all terms x u1…un with n ≥ 0 and u1,…,un ∈ SN: a variable applied to any number of strongly normalizing arguments. For example y, y I and y δ δ are in Base. By R2 (variable applied) every member of Base is in SN. Base is what every type set starts from.

For a set S of terms, write cl(S), the closure of S, for S together with every term that reaches a member of S by safe head steps. For example cl({K}) contains K, (λb.K) y and K K y.

A type set is a set T of terms that satisfies three conditions. They are called the SN condition, the Base condition and the closure condition.

SN
T ⊆ SN. Every member of T is strongly normalizing. This is W1 (inside SN), the purpose.
Base
Base ⊆ T. Needed for W5 (variables) and for W2 (arrow). Every type set contains the same set Base. So for every variable x and all strongly normalizing terms u and v, the terms x, x u and x u v are in every type set, and so on for any number of arguments.
closure
cl(T) ⊆ T. Equivalently: if s →h s′ is safe and s′ ∈ T, then s ∈ T. Needed for W3 (abstraction). Written out: if t[u/x] u1…un ∈ T and u ∈ SN, then (λx.t) u u1…un ∈ T, for every n ≥ 0. Membership survives undoing a head step that discards nothing dangerous. Only the argument u has to be asked about. The step may have thrown u away, so nothing is known about it. The other arguments u1,…,un are subterms of a member of T, so they are in SN already, by the SN condition and R1 (subterms). SN has this property by R3 (safe head step).

In short, a type set is a set between Base and SN that is closed under undoing safe head steps. The definition talks about terms and steps only. It does not mention type expressions. Those come only in §10, as names for some of the type sets.

A picture to carry through the page. A type set is, roughly, a set of values, that is, of strongly normalizing abstractions, together with every term that reaches one of them by safe head steps, together with the terms that get stuck at a variable, which belong to every type set. “Roughly” because a type set may contain a term and not the term that its head step leads to; §36 makes the picture exact and says what the word hides.

Definition · Gen(S) and Min

For a set S of strongly normalizing terms, Gen(S) = cl(Base ∪ S). It is called the set generated by S.

Min = Gen(∅) = cl(Base).

Lemma M · Three facts about type setshere, reviewed

M1
Largest. SN is a type set, and every type set is inside it.
M2
Generated. For a set S of strongly normalizing terms, Gen(S) is a type set, the smallest one that contains S. A term t is in it if and only if t ∈ SN and its head steps lead to a member of S or of Base. Zero head steps are allowed.
M3
Smallest. Min is inside every type set. Every member of Min has a free variable, so Min has no closed member.
Proof

M1. The SN condition holds trivially, the Base condition is R2 (variable applied), and the closure condition is R3 (safe head step). A type set is inside SN by the SN condition.

M2. The members of S are in SN by assumption and the members of Base by R2 (variable applied), and undoing a safe head step keeps a term in SN, by R3 (safe head step). So the SN condition holds, and the Base condition and the closure condition hold by construction. Any type set that contains S contains Base by the Base condition and satisfies the closure condition, so it contains Gen(S).

For the membership condition: a member reaches Base ∪ S by safe head steps, and it is in SN by the SN condition. In the other direction, if t ∈ SN then every argument met along its head steps is in SN, so those head steps are safe.

M3. Every type set contains Gen(∅), by M2 (generated). A member of Base has a free variable, the variable that is applied, and undoing a head step never removes a free variable. ∎

Sets that satisfy these three conditions are known as saturated sets, after Tait. Girard’s reducibility candidates are defined by a different and stronger list of conditions, and §35 compares the two.

Type sets differ from type expressions more than the shared word suggests. There are far more of them, so most type sets have no type expression that names them; §11 counts. One term is in many type sets at once. And membership is a fact about how the term runs, whether or not any rule can derive it. The proof never uses a particular type set built by hand, such as the G of the next examples. Such type sets matter because ∀ will range over all type sets, and not over type expressions. So it ranges over the hand-built ones too.

Example · The largest and the smallest type set

SN is the largest, by M1 (largest). It contains I, K, δ and I I, and it does not contain Ω.

Min is the smallest, by M3 (smallest). It contains Base, for instance y and y δ δ, and also (λz.y) I, whose head step leads to y. It does not contain I, or any other closed term.

Example · A type set built from two terms

Let G = Gen({K, I I}). Members:

  • K and I I, the two chosen terms.
  • y, y δ δ and y (I I): members of Base.
  • I (I I) and (λz.K) y: one head step leads to a chosen term.
  • K K y: two head steps lead to K, through (λb.K) y.
  • (λz.z K) y: one head step leads to y K, which is in Base.

Not members:

  • I. It is in SN and has no head step, and it is neither chosen nor in Base.
  • K K. Its head step gives λb.K, an abstraction that is not K.
  • λx.K x. It has no head step, although one step inside it gives K.
  • Ω and K I Ω. They are not in SN.

Example · A member can leave by running

I I is in G, and I I → I, but I is not in G. A type set need not keep a term while it runs. The same is true of Gen({I I}), which contains I I and not I; §23 and §35 use that type set. The other direction cannot happen: if I is in a type set, then I I is in it too, by the closure condition. Nothing later needs a type set to keep a term while it runs.

Example · Sets that are not type sets

  • ∅ fails the Base condition.
  • {I} fails the Base condition and the closure condition.
  • Base itself fails only the closure condition, which asks for (λz.y) I. Its closure cl(Base) is Min.
  • The set of all terms, and SN with Ω added, fail the SN condition.
  • Min with I added and nothing more fails only the closure condition, which asks for I I as well.

Definition · Two hand-built type sets

TI = Gen({I}).

TK = Gen({K}).

Later examples use these two to check which terms belong to other sets. TI contains I, I I and (λz.I) y, and does not contain K, δ or λx.I x. TK is the same with K in the place of I.

§6Why the definition is not simpler

Uses §5 Type sets. Used by §15, §30.

Could the definition be simpler? The measure is the list of requirements W1 to W5 at the end of §4.

W1 (inside SN) is the SN condition. The Base condition and the closure condition are what W2 (arrow), W3 (abstraction) and W5 (variables) force, as narrow points 2, 3 and 4 show. W4 (intersection) is used in narrow point 2 and proved in §8.

The narrow points show that the conditions cannot be weakened in the ways tried. They do not show that this list of conditions is the only one that works. §35 gives another.

Each narrow point puts a simpler definition of a type set on trial. A set qualifies if it satisfies the definition on trial. The trial fails if some requirement fails for the sets that qualify.

Narrow point 2 · Less than the Base condition

Goal
A definition under which every member of a type set is strongly normalizing (W1), the arrow of two type sets is a type set (W2), an intersection of type sets is a type set (W4), and every type set contains every variable (W5).
Try
Keep the SN condition, leave the closure condition aside, and ask for less than the Base condition. Four ways are tried in turn. Each one repairs the one before it. W5 (variables) alone would rule out the first two. They are tried without it, because they show that W2 and W4 already force every type set to have members, and all type sets to share some.
Breaks
  1. Ask nothing more. The empty set qualifies, and so does SN. But ∅ ⇒ SN is the set of all terms, because “for every u ∈ ∅” asks nothing. It contains Ω, which is not in SN. So ∅ ⇒ SN fails the SN condition and does not qualify, and W2 (arrow) fails. A type set has to have a member.
  2. Ask only that the set is not empty. Then {I} and {K} qualify. Their intersection is empty and does not qualify, so W4 (intersection) fails. All type sets have to have members in common. W5 (variables) says which: at least the variables.
  3. Ask only for the variables. The set Var of all variables qualifies. But Var ⇒ Var is empty, because t x is an application and never a variable. So Var ⇒ Var does not contain the variables and does not qualify, and W2 (arrow) fails.
  4. Ask only for the members of Base with n ≤ 1. That is a variable alone or applied to one argument. Let U be exactly the set on trial: the variables and the terms x u with u ∈ SN. Then U qualifies, and so does SN. No term x u v is in U. So SN ⇒ U contains the variables and no term x u: it is exactly Var, the set of the third trial. It does not qualify, and W2 (arrow) fails. One arrow further, SN ⇒ (SN ⇒ U) contains no variable at all. Each arrow uses up one argument.
Adding the closure condition does not rescue any of the four. The empty set satisfies it. Closing {I} and {K} gives cl({I}) and cl({K}), which are still disjoint, because a term has at most one head step. Closing Var or U adds only abstractions applied to arguments, so the same terms are still missing.
Hence
  1. A variable in T serves as the argument: if x ∈ T and t ∈ T ⇒ U, then t x ∈ U, so t x ∈ SN, so t ∈ SN by R1 (subterms). This gives W1 (inside SN) for T ⇒ U.
  2. W2 (arrow) says that T ⇒ U is a type set, and W5 (variables) says that a type set contains the variables. So T ⇒ U must contain the variables. This follows from W2 and W5 and is no new requirement. It needs x u ∈ U for every u ∈ T. SN qualified in every trial, so T may be SN, and then all we know about u is that it is in SN.
  3. Each arrow adds one argument to what is asked: one arrow deeper it reads x u1 u2 ∈ U. Arrows nest to any depth. So the condition that keeps itself true under ⇒ is the Base condition, for every n.
  4. The Base condition puts the same set, Base, inside every type set. So an intersection of type sets is never empty, which W4 (intersection) needs.

Narrow point 3 · Undoing a step

Goal
W3 (abstraction): if t[u/x] ∈ U for every u ∈ T, then λx.t ∈ T ⇒ U. By the definition of ⇒, the claim λx.t ∈ T ⇒ U means (λx.t) u ∈ U for every u ∈ T. W3 hands us only t[u/x] ∈ U, and t[u/x] is what (λx.t) u becomes after one step. So if every type set that contains the term after that step also contains the term before it, then W3 holds.
Try
Replace the closure condition by the simplest condition that does this: every type set is closed under undoing a step, any step.
Breaks
Twice. First, a step may throw its argument away. The variable y is in every type set, and (λx.y) Ω steps to y, but it is not in SN, because Ω is still inside it. So ask at least that the argument is in SN. Second, even then a step inside an abstraction can hide a loop. (λz.y) δ is in every type set, since a head step with a strongly normalizing argument takes it to y. Undoing a step inside it gives (λz.(λx.y) (z z)) δ, and the argument z z is in SN. But this term also steps to (λx.y) (δ δ), which is not in SN. Either way a term that is not in SN would be in every type set, so W1 (inside SN) fails.
Hence
The closure condition undoes only a head step, and only if the head step is safe. R3 (safe head step) says that SN is closed in exactly this way, so at least one type set exists. W3 (abstraction) still follows: the step from (λx.t) u to t[u/x] is a head step, and it is safe because u comes from a type set.

Narrow point 4 · Trailing arguments

Goal
W2 (arrow) again: the arrow of two type sets has to be a type set. The closure condition is now one of the conditions, so T ⇒ U has to satisfy it too.
Try
State the closure condition for the bare form only: if t[u/x] ∈ T and u ∈ SN, then (λx.t) u ∈ T.
Breaks
W2 (arrow) fails. Let U be the smallest set with the Base condition and this short rule. It qualifies. Its members have two forms: x u1…un, or an abstraction applied to exactly one argument. Then I ∈ U ⇒ U, and the short rule for U ⇒ U asks for (λz.I) y ∈ U ⇒ U, which means (λz.I) y v ∈ U for v ∈ U. That term has neither form, so it is not in U. So U ⇒ U does not satisfy the short rule and does not qualify.
Hence
Membership in T ⇒ U is tested by adding one argument. So a head step allows arguments after the redex, as in (λx.t) u u1…un, and it survives one more argument. Then the closure condition passes through ⇒ in one line.

§7The collection of type sets

Uses §5 Type sets. Used by §16, §36, §39.

This section describes the collection of all type sets: other ways to state the definition, how type sets are ordered by inclusion, and which terms they tell apart. The soundness theorem does not use it. §16, §39 and §36 do.

The picture is this. Outside Min, head steps arrange the strongly normalizing terms into trees. Each tree has an abstraction at its root, and above the root the terms whose head steps end at that abstraction. A type set is Min together with a part of each tree that is closed under moving away from the root. Gen({a}) is Min together with a and everything beyond a, away from the root.

Lemma E · The definition in other wordshere, reviewed

E1
Min inside. For a set with the closure condition, the Base condition holds if and only if Min ⊆ T.
E2
One argument at a time. For a set with the SN condition, the Base condition holds if and only if both of these hold: every variable is in T, and if s ∈ T is a variable applied to arguments and u ∈ SN, then s u ∈ T. Base is built one argument at a time.
E3
Whole term in SN. For a set with the SN condition, the closure condition holds if and only if this holds: if s ∈ SN, s →h s′ and s′ ∈ T, then s ∈ T. “The argument is in SN” becomes “the whole term is in SN”.
E4
Generated. T is a type set if and only if T = Gen(S) for some set S of strongly normalizing terms. Every type set is built the way G was: it is the closure of Base and some chosen strongly normalizing terms.

Put together: a type set is a set between Min and SN that contains every strongly normalizing term whose head step leads into it.

Proof

E1. Min is cl(Base). So a set with the closure condition that contains Base contains Min. And Base ⊆ Min.

E2. From the two clauses, x u1…un ∈ T follows by induction on n. Conversely, let s = x u1…un be in T. By the SN condition it is in SN, so its arguments are, by R2 (variable applied). So if u ∈ SN, then s u is in Base.

E3. Let s →h s′ with argument u, and s′ ∈ T. Then s′ ∈ SN, by the SN condition. If u ∈ SN, then s ∈ SN, by R3 (safe head step). If s ∈ SN, then u ∈ SN, as a subterm of s, by R1 (subterms). So the head step is safe if and only if s ∈ SN.

E4. Gen(S) is a type set by M2 (generated). And a type set T is the smallest type set that contains T, which is Gen(T). ∎

Lemma L · Type sets generated by one term follow head stepshere, reviewed

Let a, b and c be strongly normalizing terms, and let S and S′ be sets of strongly normalizing terms.

L1
Unions. Gen(S) ⊆ Gen(S′) if and only if S ⊆ Gen(S′). Also Gen(S ∪ S′) = Gen(S) ∪ Gen(S′), and the same holds for the union of any nonempty collection of sets. So every type set T is the union of the type sets Gen({a}) with a ∈ T.
L2
One term inside another. Gen({a}) ⊆ Gen({b}) if and only if a ∈ Min or a reaches b by zero or more head steps. In particular, if a →h b, then Gen({a}) ⊆ Gen({b}).
L3
Chain. If a ∈ Min, then Gen({a}) = Min. If a ∉ Min, let a = a0 →h a1 →h … →h ak be all the head steps of a. Then ak is an abstraction, and the type sets of the form Gen({c}) that contain a are exactly Gen({a0}) ⊊ Gen({a1}) ⊊ … ⊊ Gen({ak}). The smallest type set that contains a grows along the head steps of a. It is largest at the abstraction where the head steps end.
L4
Not for other steps. The inclusion of L2 can fail for a step that is not a head step. λx.K x → K is such a step, and Gen({λx.K x}) is not inside Gen({K}).
Proof

L1. Gen(S′) is a type set, and Gen(S) is the smallest type set that contains S, by M2 (generated). So if S ⊆ Gen(S′) then Gen(S) ⊆ Gen(S′). The other direction holds because S ⊆ Gen(S).

For the union: a term reaches a member of A ∪ B by safe head steps if and only if it reaches a member of A or a member of B. So cl(A ∪ B) = cl(A) ∪ cl(B), and then Gen(S ∪ S′) = cl(Base ∪ S ∪ S′), which is Gen(S) ∪ Gen(S′). A type set T is Gen(T), by E4, and that is the union of the sets Gen({a}) with a ∈ T.

L2. By L1 the inclusion holds if and only if a ∈ Gen({b}), and Gen({b}) = Min ∪ cl({b}). Every head step of a strongly normalizing term is safe, because its argument is a subterm. So a ∈ cl({b}) if and only if a reaches b by head steps.

L3. If a ∈ Min, then cl({a}) ⊆ Min by the closure condition for Min, so Gen({a}) = Min ∪ cl({a}) = Min.

Let a ∉ Min. The head steps of a end, because a ∈ SN, and they end at a term ak with no head step. That term is an abstraction or a member of Base. It is not in Base, or a would be in Min. So it is an abstraction, and no ai is in Min. By L2, Gen({c}) contains a if and only if a reaches c by head steps, that is, if and only if c is one of a0,…,ak. The inclusions hold by L2. They are strict because ai+1 is not in Gen({ai}): it is not in Min, and it does not reach ai by head steps, or the head steps of a would go round in a circle and never end.

L4. λx.K x is an abstraction. It has no head step, it is not in Min, and it is not K. So by L2 it is not in Gen({K}). ∎

Example · A chain of generated type sets

The head steps of K K y are K K y →h (λb.K) y →h K. By L3,

Gen({K K y}) ⊊ Gen({(λb.K) y}) ⊊ Gen({K}) = TK

and these three are the only type sets of the form Gen({c}) that contain K K y. In the same way I I →h I gives Gen({I I}) ⊊ Gen({I}) = TI. And Gen({y δ δ}) = Min, because y δ δ is in Min.

Lemma · Type sets tell terms aparthere, reviewed

Let a and b be strongly normalizing terms. Then a and b belong to the same type sets if and only if they are the same term, or both are in Min.

So the statement “every type set that contains I I contains I” is false: Gen({I I}) contains the first and not the second. Outside Min, no two different terms are members of exactly the same type sets, however they are related by steps. §39 draws the consequence: an equality between terms is never built into the semantics, and has to be added as a type set.

Proof

a and b belong to the same type sets if and only if Gen({a}) = Gen({b}), because Gen({a}) is the smallest type set that contains a, by M2 (generated), and likewise for b.

If both are in Min, then Gen({a}) = Min = Gen({b}), by L3 (chain). If they are the same term, there is nothing to show.

Suppose Gen({a}) = Gen({b}). If a ∈ Min, then b ∈ Gen({a}) = Min. Otherwise, by L2 (one term inside another) applied in both directions, a reaches b by head steps and b reaches a by head steps. The head steps of a strongly normalizing term cannot go round in a circle, so a and b are the same term. ∎

§8Arrow, intersection and union

Uses §5 Type sets. Used by §9, §10.

Type sets are combined in two ways, by the arrow and by intersection. Each has to give a type set again, which is what W2 (arrow) and W4 (intersection) asked for. The arrow was defined in §4.

The arrow

Example · Terms that are in many arrows at once

  • I ∈ T ⇒ T for every type set T. Take u ∈ T. It is in SN by the SN condition, and x[u/x] = u ∈ T, so (λx.x) u ∈ T by the closure condition.
  • K ∈ T ⇒ (U ⇒ T) for all type sets T and U. Take u ∈ T and v ∈ U. Both are in SN, by the SN condition. From u ∈ T, the closure condition gives (λy.u) v ∈ T, and the closure condition again gives (λx.λy.x) u v ∈ T.

Example · An arrow between two hand-built type sets

Take TK ⇒ TI, with TK = Gen({K}) and TI = Gen({I}) from §5. A member has to send K, every variable applied to arguments, and everything that reaches these by head steps, into TI. Members:

  • λx.I. Whatever u is, (λx.I) u reaches I in one head step.
  • λx.x I y. With K for x it runs K I y → (λb.I) y → I. With a variable applied to arguments for x, the result is again a variable applied to arguments.
  • y, a variable. y u is in every type set.
  • K I, which is an application and not an abstraction. K I u → (λb.I) u → I.

Not members:

  • I. The term I K is not in TI: its head step leads to K, which is not I and not in Base.
  • K and δ. K K and δ K both reach λb.K, which is not in TI.

Membership is a test of behaviour on the members of T. It does not ask that the term be an abstraction, and it depends on both sides of the arrow.

Arrow lemma · The arrow of two type sets is a type settextbook

If T and U are type sets, then T ⇒ U is a type set.

Proof

SN condition. Let t ∈ T ⇒ U. A variable x is in T, because Base ⊆ T. So t x ∈ U, and t x ∈ SN by the SN condition for U. Then t ∈ SN by R1 (subterms).

Base condition. Let s ∈ Base and take v ∈ T. Then v ∈ SN by the SN condition for T, so s v is again in Base, and Base ⊆ U by the Base condition for U.

Closure condition. Let s →h s′ be safe with s′ ∈ T ⇒ U, and take v ∈ T. Then s′ v ∈ U. And s v →h s′ v is a safe head step, with the same argument. So s v ∈ U by the closure condition for U. ∎

Example · The arrow into Min is negation, and it is intuitionistic

For a type set T, the type set T ⇒ Min is what the negation of T will be once names exist: §10 reads A → ∀X.X as ⟦A⟧ ⇒ Min. It is not the complement of T inside SN, and it does not behave like one.

  • T ∩ (T ⇒ Min) is not empty: it contains Base, and for T = SN it contains λy.z, since (λy.z) u →h z. But it has no closed member: a closed t in it would give t t ∈ Min, and t t is closed, while Min has no closed member by M3 (smallest).
  • T ∪ (T ⇒ Min) is not SN: for T = TI, the term δ is in neither part, because δ ∉ TI and δ I → I I ∉ Min.

Read as statements about a proposition A: “A and not A” has no closed proof, and “A or not A” has no proof at all for some A. That is the negation of intuitionistic logic, which is the logic of System F read as a proof system. A complement, which would make the second statement true for every T, exists in one of the collections of §36 and names nothing a rule could use.

The intersection over all type sets

The intersection over all type sets is the operation that gives System F its power. A term that is given a “for all X” type expression should work at every type set. As a set of terms, that is an intersection over all type sets.

Definition · Intersection over all type sets

Let F be any function that gives a type set F(C) for each type set C, for example F(C) = C ⇒ C. Then

⋂C F(C) = { t : t ∈ F(C) for every type set C }

Here C runs over all type sets in the sense of §5, the hand-built ones included.

Definition · ID and BOOL

ID = ⋂C (C ⇒ C).

BOOL = ⋂C (C ⇒ (C ⇒ C)).

Example · Members of ID

ID contains I, since I ∈ C ⇒ C for every C. It also contains I I and λx.I x: applied to u, both reach u by head steps. It does not contain K. Test with C = TI and the argument I: K I → λb.I, which is not in TI. No typing rule in §13 mentions TI, and it keeps K out of ID all the same.

Example · Members of BOOL

A member of BOOL, given two arguments from any type set, must land in that type set. Members:

  • K and λx.λy.y, the two ways to pick one of two arguments.
  • I K and (λz.K) y, which reach K by a head step.
  • y and y δ δ, as in every type set.

Not a member: I. Test it with C = TK and both arguments K: I K K → K K → λb.K, which is not in TK. So BOOL has infinitely many members, and not two.

Intersection lemma · An intersection of type sets is a type settextbook

Let I be a nonempty set, and let F give a type set F(i) for each i ∈ I. The intersection indexed by I is

⋂i∈I F(i) = { t : t ∈ F(i) for every i ∈ I }

and it is a type set. In particular ⋂C F(C) is a type set: it is the case in which I is the collection of all type sets. The intersection of all type sets is Min, by M3 (smallest).

The lemma is stated for any index set because later sections intersect over other ones, and each time this lemma is the whole proof: over all families in §24, over the members of a type set in §27 and §29, and over a kind in §32. The index set has to be nonempty: the intersection of no sets at all is the set of all terms, which is not a type set.

Proof

SN condition. I has a member i, and every member of the intersection lies in F(i), which is inside SN.

Base condition and closure condition. Each says that certain terms are members. They hold in every F(i), so they hold in the intersection. ∎

The intersection ⋂C F(C) is a type set, so it is one of the sets that it was intersected over. A definition is called impredicative if it defines a set by quantifying over a collection that contains that set. This one is. Narrow point 5 in §11 says why the intersection runs over all type sets, and not over type expressions.

The union

Union is a third operation that gives a type set again. The soundness theorem does not use it. §20 and §22 do.

Union lemma · A union of type sets is a type sethere, reviewed

The union of a nonempty collection of type sets is a type set.

Proof

Each of the three conditions asks something of single terms. A member of the union is in some type set of the collection, so it is in SN. Base is inside every type set of the collection. If s →h s′ is safe and s′ is in a type set of the collection, then s is in the same one. ∎

Example · G as a union

G = Gen({K, I I}) = TK ∪ Gen({I I}). This follows from the membership condition in M2 (generated): the head steps of a member lead to K, to I I, or to a member of Base. The members K, (λz.K) y and K K y come from TK. The members I I and I (I I) come from Gen({I I}). Min is in both.

§9Four facts

Uses §8 Arrow, intersection and union. Used by §12, §24, §32.

There are still no type expressions and no typing rules. There are sets of terms, and four facts about them.

Lemma · Four factstextbook

Let T, U and D be type sets, and let F give a type set F(C) for each type set C.

apply
If t ∈ T ⇒ U and u ∈ T, then t u ∈ U.
abstract
If t[u/x] ∈ U for every u ∈ T, then λx.t ∈ T ⇒ U. This is W3 (abstraction).
generalize
If t ∈ F(C) for every type set C, then t ∈ ⋂C F(C).
instantiate
If t ∈ ⋂C F(C) and D is a type set, then t ∈ F(D).

Generalize and instantiate hold in the same words for an intersection indexed by any nonempty set I, with “every i ∈ I” in the place of “every type set C”: if t ∈ F(i) for every i ∈ I, then t ∈ ⋂i∈I F(i); and if t ∈ ⋂i∈I F(i) and j ∈ I, then t ∈ F(j). Both are the definition of the intersection read in the two directions.

Proof

Apply, generalize and instantiate are the definitions of ⇒ and ⋂, read in the other direction.

Abstract. Take u ∈ T. It is in SN by the SN condition, so (λx.t) u →h t[u/x] is a safe head step. Since t[u/x] ∈ U, the closure condition gives (λx.t) u ∈ U. ∎

Three of the four are definitions read backwards. Only abstract uses the conditions, and it uses the SN condition and the closure condition once each. The work was done in §5 and §8, in making sure that ⇒ and ⋂ never leave the collection of type sets.

Example · The four facts at work

Claim: λf.λx.f (f x) is in ⋂C ((C ⇒ C) ⇒ (C ⇒ C)). The term applies its first argument twice.

  1. Fix any type set C. Take g ∈ C ⇒ C and u ∈ C.
  2. Apply: g u ∈ C. Apply again: g (g u) ∈ C.
  3. Abstract over x: λx.g (g x) ∈ C ⇒ C.
  4. Abstract over f: λf.λx.f (f x) ∈ (C ⇒ C) ⇒ (C ⇒ C).
  5. Generalize: C was arbitrary, so the term is in the intersection.

Nothing here looked inside C. It could be SN, TK, or a type set nobody has described.

Example · Self-application

Recall that ID = ⋂C (C ⇒ C). Claim: δ ∈ ID ⇒ ID.

  1. Take any u ∈ ID.
  2. Instantiate with D = ID: u ∈ ID ⇒ ID.
  3. Apply: u u ∈ ID.
  4. Abstract: λx.x x ∈ ID ⇒ ID.

Since I ∈ ID, apply gives δ I ∈ ID, so δ I ∈ SN. The instantiate line uses ID at itself. That is allowed because ID was defined by intersecting over all type sets, and ID is one of them.

The sets also discriminate: δ ∉ ID. Otherwise apply would give δ δ = Ω ∈ ID.

Part III · System F

§10Type expressions are names

Uses §8 Arrow, intersection and union. Used by §11, §12.

System F is now a notation for some of these sets, together with a list of facts about them.

Definition · Type expressions are names

A type expression is a variable X, an arrow A → B, or ∀X.A. The variables X, Y of type expressions are a second sort of variable, separate from the variables of terms, which are called term variables from here on. The arrow groups to the right, so X→X→X means X→(X→X).

In ∀X.A the variable X is bound. A variable is free in a type expression if it occurs there outside every ∀X.

A type expression is closed if no variable is free in it.

A[B/X] is A with B in place of every free occurrence of X.

An assignment ρ gives a type set ρ(X) for each variable X.

The set that a type expression names under ρ is:

⟦X⟧ρ = ρ(X)
⟦A → B⟧ρ = ⟦A⟧ρ ⇒ ⟦B⟧ρ
⟦∀X.A⟧ρ = ⋂C ⟦A⟧ρ[X↦C]

Here ρ[X↦C] is ρ changed to send X to C. The third clause needs each ⟦A⟧ρ[X↦C] to be a type set. Lemma N, which follows the examples, proves that.

Example · One type expression, two assignments

Take the type expression X → X.

  • With ρ(X) = SN it names SN ⇒ SN.
  • With ρ(X) = TK it names TK ⇒ TK.

I is in both sets. λx.I is in SN ⇒ SN and not in TK ⇒ TK: it sends K to a term whose head step leads to I, and I is not in TK. A type expression with free variables names a different set for each assignment.

Example · Closed type expressions

A type expression without free variables names the same set under every assignment. ∀X.X→X names ID. ∀X.X names Min. ∀X.X→X→X names BOOL.

Example · Working out a named set

∀X.∀Y.X→Y names ⋂C ⋂D (C ⇒ D), and that set is SN ⇒ Min. Every C ⇒ D contains SN ⇒ Min: a term that sends SN into Min sends C into D, because C ⊆ SN and Min ⊆ D. And SN ⇒ Min is one of the sets intersected. It contains the variable y and no closed term: a closed member applied to I would be a closed member of Min.

Lemma N · Every type expression names a type settextbook

N0
Free variables. If ρ and ρ′ agree on the free variables of A, then ⟦A⟧ρ = ⟦A⟧ρ′.
N1
Type set. ⟦A⟧ρ is a type set, for every type expression A and every ρ.
N2
Substitution. ⟦A[B/X]⟧ρ = ⟦A⟧ρ[X↦⟦B⟧ρ]. Replacing X by the type expression B names the same set as sending X to the set that B names. For example, (X → X)[∀Y.Y→Y / X], and X → X with ρ(X) = ID, both name ID ⇒ ID.
Proof

All three by induction on A. For N1 (type set), a variable names ρ(X), which is a type set by assumption. An arrow is covered by the arrow lemma, and ∀ by the intersection lemma. N0 (free variables) and N2 (substitution) are unfolding the three clauses. The ∀ case of N2 (substitution) uses N0 (free variables), because the bound variable can be taken to be not free in B. ∎

Uses §10 Type expressions are names. Used by §14, §17.

Narrow point 5 · ∀ over type expressions

Goal
Say which set of terms ∀X.A names.
Try
Let C run over type expressions and not over sets. In System F a term with the type expression ∀X.A may be used at A[B/X] for any type expression B. So let ∀X.A name the terms that are in the set named by A[B/X], for every type expression B.
Breaks
The definition is circular. The set that a type expression names is defined from the sets that shorter type expressions name. But B may be ∀X.A itself, or something longer. With A = X → X and B = ∀X.X→X, the instance (∀X.X→X) → (∀X.X→X) contains the type expression being defined, twice.
Hence
The definition of names lets C run over all type sets in the sense of §5. Those are sets, and the collection of them was fixed by the three conditions before ⇒ or ∀ were mentioned. So it is one intersection of sets that already exist. The result is again a type set, and so it is one of the sets it was intersected over. So the definition is impredicative, in the sense of §8. Ordinary set theory allows it. Predicative foundations do not, and this is the one place where the proof needs a strong metatheory, that is, a strong theory to carry the proof out in. The idea is Girard’s.

Lemma · Most type sets have no namehere, reviewed

There are countably many type expressions and uncountably many type sets. So almost every type set is named by no closed type expression.

Proof

A type expression is a finite string of symbols, so there are countably many. For the type sets, let S be any set of closed normal forms, and take the type set Gen(S) of §5. Its closed normal forms are exactly the members of S: members of Min have free variables, and what the closure condition adds always has a head step. So different S give different type sets, and there are uncountably many sets S. ∎

So a variable X ranges over far more than type expressions can name. Type sets built by hand, like TI in §5, are legitimate values for X. No rule mentions them, yet every member of the set that ∀X.X→X names has to send each of them into itself.

§12Judgments

Uses §9 Four facts, §10 Type expressions are names. Used by §13.

Definition · Judgment

A context Γ is a list x1:A1, …, xn:An of distinct term variables, each with a type expression.

A judgment consists of a context Γ, a term t and a type expression A.

The judgment is true, written Γ ⊨ t : A, if the following holds: for every ρ, and for all terms u1 ∈ ⟦A1⟧ρ, …, un ∈ ⟦An⟧ρ, the term t[u1/x1,…,un/xn] is in ⟦A⟧ρ.

Example · A true judgment with no context

⊨ I : ∀X.X→X, since I ∈ C ⇒ C for every type set C.

Example · Self-application as a true judgment

x : ∀X.X→X ⊨ x x : ∀X.X→X. This is the self-application example of §9, up to its apply line.

Example · A true judgment with a context

x : X, f : X → Y ⊨ f x : Y. Take any assignment, any u ∈ ρ(X) and any g ∈ ρ(X) ⇒ ρ(Y). Then g u ∈ ρ(Y), by the definition of the arrow. One instance: ρ(X) = TK, ρ(Y) = TI, u = K and g = λx.x I y, a member of TK ⇒ TI.

Example · A true judgment about an abstraction

x : X ⊨ λy.x : Y → X. Take any u ∈ ρ(X) and v ∈ ρ(Y). Then (λy.u) v →h u is a safe head step, because v ∈ SN. So (λy.u) v ∈ ρ(X) by the closure condition, and that says λy.u ∈ ρ(Y) ⇒ ρ(X).

Example · A false judgment

x : X ⊨ x : Y is false. Send X to SN and Y to Min, and replace x by I. Then I ∈ SN, and I is not in Min. One assignment and one replacement are enough to refute a judgment.

§13The rules and the soundness theorem

Uses §9 Four facts, §12 Judgments. Used by §14, §16, §17, §35, §38.

Definition · The rules of System F

System F has five rules. Each rule concludes one judgment from at most two others.

RuleFromConclude
variablex:A is in ΓΓ ⊢ x : A
→ outΓ ⊢ t : A→B and Γ ⊢ u : AΓ ⊢ t u : B
→ inΓ, x:A ⊢ t : BΓ ⊢ λx.t : A→B

Γ, x:A is the context Γ with x:A added at the end.

A derivation is a finite list of judgments in which each judgment follows from earlier ones by one of the rules.

A judgment is derivable, written Γ ⊢ t : A, if it is the last judgment of a derivation.

A term t is typable if Γ ⊢ t : A is derivable for some Γ and some A. The rules then give t the type expression A.

A rule is true if the following holds: if the judgments it starts from are true, then the judgment it concludes is true.

The two ∀ rules leave the term unchanged. This way of presenting System F, with no annotations inside terms, is called Curry style.

Example · What a side condition prevents

x : X ⊨ x : X is true. x : X ⊨ x : ∀X.X is false: send X to SN and replace x by I, and recall that ∀X.X names Min. The rule “∀ in” would lead from the true judgment to the false one if it did not require that X is not free in the context.

Soundness theorem · The rules of System F are truetextbook

If Γ ⊢ t : A, then Γ ⊨ t : A.

Each rule except the variable rule is one of the four facts of §9. “→ out” is apply, “→ in” is abstract, “∀ in” is generalize, and “∀ out” is instantiate.

Proof

By induction on the derivation, with one case per rule. In each case the variables of Γ have been replaced by members of their sets.

  • Variable. The term that replaces x was taken from ⟦A⟧ρ.
  • → out. Apply.
  • → in. Abstract. The bound variable x is renamed if needed, so that it is not a variable of Γ and not free in the terms that replace them.
  • ∀ in. Generalize. Because X is not free in Γ, the sets ⟦Ai⟧ρ do not change while ρ(X) varies, by N0 (free variables). So the terms that replace the variables stay in their sets.
  • ∀ out. Instantiate at D = ⟦B⟧ρ, which is a type set by N1 (type set). Then N2 (substitution) turns the result into ⟦A[B/X]⟧ρ. ∎

Corollaries · Strong normalization and consistencytextbook

C1

C2

C1 (strong normalization) holds because the variables are members of every type set, so each variable can be replaced by itself. C2 is called consistency for this reason: read as a statement, ∀X.X says that everything holds, and a closed term t with ⊢ t : ∀X.X would be a proof of it.

Proof

C1. Pick any ρ. Replace each variable xi by itself. That is allowed because xi ∈ ⟦Ai⟧ρ by the Base condition. The theorem gives t ∈ ⟦A⟧ρ, and t ∈ SN by the SN condition.

C2. Such a term would be in Min, which has no closed member. The word “closed” costs nothing here: a term t with ⊢ t : A is always closed, because a free variable can enter a derivation only through the variable rule, which takes it from the context. ∎

Remark · Where the context is

Type sets are not indexed by a context. A variable is an untyped term, and by the Base condition it belongs to every type set, whatever type expression a context might give it. That does no harm, because a variable does nothing: it has no step. The context appears in two places only. In a judgment it is the list of sets that the replacing terms are taken from. In a derivation it is the list of variables that the term may have free. C2 (consistency) uses that: a term derived in the empty context is closed.

This is what lets the sets come before the rules. A set that depended on the type expressions of its variables would need those first. Proofs that compute normal forms, and not only prove strong normalization, usually cannot avoid this, and they index every set by a context.

Remark · Church style: System F with annotations

System F is often written with type expressions inside terms: λx:A.t, an abstraction ΛX.t over a variable of type expressions, and its application t [B] to a type expression. Erasing these annotations gives a term that the five rules accept. Every step of the annotated calculus either erases to a step, or is a step (ΛX.t) [B] → t[B/X], which erases to nothing and removes one Λ. So between two steps that erase to steps there are at most as many steps that erase to nothing as the term has Λs, an infinite run with annotations would give an infinite run without them, and C1 (strong normalization) covers both presentations. This argument was worked out for this page.

Curry style has a price. A derivation cannot be read off the term, so nothing on this page is something a machine could check from the term alone; and systems whose terms carry type expressions that contain terms again are covered only through an erasure argument of this kind, which §42 states in general.

Remark · What the proof asked of the collection that ∀ ranges over

The proofs of Lemma N, of the four facts, of the soundness theorem and of its corollaries use five things about the collection of all type sets, and nothing else: that every member satisfies the three conditions of §5; that the arrow of two members is a member; that the intersection of a nonempty set of members is a member; that the collection itself is not empty, so that ∀ is such an intersection; and, for C2 (consistency), that the smallest member of the collection, which is what ∀X.X names, has no closed member. For the collection of all type sets that member is Min. Any collection of type sets with these properties could take the place of the collection of all type sets as the range of ∀, with assignments taking their values in it, and the results would hold with the same proofs. §36 does this for two smaller collections, and §37 for a third. This page keeps the largest one, because it asks the least of a set; §36 says what the smaller ones give in return.

Remark · What the proof asked of terms

The same proofs use, about terms, only the following, and nothing else about what a term is. Lemma R of §2: R1 (subterms), R2 (variable applied) and R3 (safe head step). That a head step survives one more argument, with the same argument. That (λx.t) u takes a head step to t[u/x], with argument u. That a variable is in Base, that a member of Base applied to a member of SN is in Base, and that a member of Base has a free variable. And, for M2 (generated), that a member of cl(S) reaches S by safe head steps. The list was made by reading the proofs of §5 to this section, and it is the list that §38 checks for pairs of terms. Anything with an application, an abstraction, a notion of step and a set Base for which these hold carries the theory: pairs of terms, and in the same way lists of any fixed length, which give relations between several terms; and terms with further forms, such as pairs or numbers inside them, once Lemma R and the three conditions have been restated for the new forms, which is what limit 4 of §23 says has to be done. Combinators, terms built from S, K and application with no abstraction at all, carry it too, with the facts about S and K in the place of abstract: K u v and S u v w take head steps that discard or copy an argument, exactly as (λx.t) u does, and the three conditions are stated for those head steps; this was not written out for this page. What the list does not mention is as telling: that a term has one of three forms, or that steps are confluent, is never used on the main line. A different route is open whenever a translation into terms sends each step of the other system to one or more steps, or to none with only finitely many such in a row: then the erasure lemma of §42 gives strong normalization for the other system from the theorem for terms, with no semantics of its own.

§14Derivable and true

Uses §11 ∀ ranges over all type sets, §13 The rules and the soundness theorem. Used by §15, §18, §44.

The soundness theorem says that every derivable judgment is true. Two questions are left. What keeps that so if a new type expression is added? And is every true judgment derivable?

Narrow point 6 · Names must be checked

Goal
Keep the rule “∀ out” true, and keep C1 (strong normalization).
Try
Use ∀X.A at any type expression B without checking what B names. After all, instantiate is trivial.
Breaks
Twice. System F has no type expression that names ∅, and Lemma N is the reason. Suppose one were added, called Empty.
  1. “∀ out” is no longer true. The judgment x : ∀X.X ⊢ x : Empty is derivable, by “∀ out” with B = Empty. It is not true: ∀X.X names Min, the variable y is in Min, and y is not in ∅. Instantiate needs D to be one of the sets that were intersected over, and those are the type sets.
  2. Even true rules stop certifying strong normalization. Add the rule “from Γ ⊢ x : Empty conclude Γ ⊢ t : A”, which is true because nothing is in ∅. Then x : Empty ⊢ Ω : A, and λx.Ω gets the type expression Empty → A. It is closed, it is typable, and it is not in SN. The judgment is true and tells nothing: Empty → A names ∅ ⇒ U, the set of all terms.
Hence
Lemma N. Having let ∀ range over type sets in narrow point 5, one has to show that every type expression names a type set. C1 (strong normalization) rests on N1 (type set): the set named by the type expression of a term is a type set, so its members are strongly normalizing.

The second question has the answer no.

Lemma · True and not derivablehere, reviewed

The judgment ⊨ (λz.I) y : ∀X.X→X is true and not derivable. So the soundness theorem has no converse.

Proof

It is true, because (λz.I) y is in ID by the closure condition. It is not derivable: the variable y is not in the empty context, so the rules cannot give it a type expression. ∎

A sharper case replaces y by a closed strongly normalizing term that is not typable in System F. Such terms are known to exist; this is quoted from the literature and not shown here. The result is closed, is in ID, and is not typable. With intersection types this cannot happen: §21 shows that then every strongly normalizing term is typable.

So the set that a type expression A names is not the set of terms that the rules give A. The second set is inside the first, by the soundness theorem, and the lemma shows that it can be strictly inside.

Remark · Two readings of the rules

A derivation of ⊢ t : A is a finite object that a machine can check. The theorem turns it into a guarantee about every run of t. So the rules are a proof system for statements of the form “t is in the set named by A”. The theorem says that this proof system is sound: what it derives is true. The lemma “True and not derivable” says that it is not complete: some true statements have no derivation.

The same rules have a second reading. Read A → B as “A implies B” and ∀X.A as “A, for every proposition X”. Then a type expression is a formula, a closed term t with ⊢ t : A is a proof of A, and the rules are those of second-order propositional logic with implication. C2 (consistency) says that this logic does not prove everything. The match between the two readings is the Curry–Howard correspondence.

Where the difficulty comes from

Each narrow point goes back to one of three demands that the theorem makes.

  • Steps in any order, anywhere. If only the head step were allowed, a discarded argument would never be run, and undoing a head step would never bring in a term that is not in SN. Because any redex may be reduced, the closure condition asks for a safe head step and for nothing more general. This is narrow point 3.
  • Open terms. The theorem covers terms with free variables and steps under λ. That is what puts the variables into every type set, and with them all of the Base condition. There is a second reason for open terms. The empty set cannot be a type set, by narrow point 2, so even the type set that ∀X.X names has members, and C2 (consistency) asks that none of them is closed. This is narrow point 2.
  • ∀ over all type sets. Without ∀ one can define a set for each type expression directly, by recursion on the type expression, and closure under undoing head steps is then a lemma about those sets. With ∀ that recursion is circular. So the type sets have to be defined beforehand, as all sets that satisfy certain conditions. The conditions then have to be chosen so that they survive ⇒ and ⋂, and every type expression has to be shown to name such a set. These are narrow points 5, 4 and 6.

§16How much is about strong normalization

Uses §3 SN is generated by three rules, §7 The collection of type sets, §13 The rules and the soundness theorem. No later section uses it.

Very little of the proof is about strong normalization. It uses three facts about the set SN, and they follow from Lemma R. Applied to a variable: if t x is in the set, then so is t. Variable applied: if u1,…,un are in the set, then so is x u1…un. Safe head step: if s →h s′, and s′ and the argument of the step are in the set, then so is s.

Replace SN everywhere by any set Good of terms with these three properties, and “strongly normalizing” by “in Good”. Every definition and proof that the theorem and its corollaries use goes through unchanged: the definition of a type set, the arrow lemma, the intersection lemma, the four facts, Lemma N, the theorem and both corollaries. The conclusion is that every typable term is in Good. Three things use more about SN, namely that every subterm of a member of SN is in SN: the membership condition in M2 (generated), the forms E2 (one argument at a time) and E3 (whole term in SN) of Lemma E, and Lemma L. Strong normalization is the case Good = SN, and it enters only through Lemma R. This generalization goes back to Mitchell, and Gallier’s survey works it out. It is the same move as in the remark of §13 on what the proof asked of the collection that ∀ ranges over, one level down: there the collection of sets was replaced, here the largest set.

The weakly normalizing terms are another set with the three properties. Variable applied holds because a run of x u1…un runs the arguments one at a time, and safe head step because a normal form of s′ is reached from s through its head step. Applied to a variable needs a sentence: if t x has a normal form, then so does t. By the standardization theorem, quoted here, a term with a normal form reaches it by the run that always takes the leftmost step. The leftmost run of t x takes the leftmost steps of t until t has become an abstraction λy.t′, if it ever does; if it never does, that run is the leftmost run of t with x appended, so t has a normal form. If it does, the run continues with (λy.t′) x → t′[x/y], and the leftmost run of t′[x/y] ends in a normal form. The same steps can be taken in t′, because replacing a variable by a variable neither creates nor removes a redex, and they end in a term m with m[x/y] equal to that normal form; a redex in m would be a redex in m[x/y], so m is a normal form too. So λy.t′, and with it t, has a normal form. This argument was worked out for this page.

§17How strong the proof has to be

Uses §11 ∀ ranges over all type sets, §13 The rules and the soundness theorem. Used by §41.

One place in the proof is stronger than the rest: the intersection over all type sets, which is impredicative (narrow point 5). That strength cannot be avoided. The theorem cannot be proved in second-order arithmetic, which is arithmetic that can also quantify over sets of numbers. The reason is a diagonalization on top of a result of Girard’s, which is quoted here and not proved.

  • Quoted. The functions on numbers that System F can define are exactly those that second-order arithmetic proves total.
  • The diagonalization. A theory that proves strong normalization for System F proves that the evaluator of System F is a total function. If that theory were second-order arithmetic, the evaluator would be definable in System F. Then so would “run program n on input n and add one”, which differs from every definable function.

The proof on this page fits in third-order arithmetic, one level up, and in ordinary set theory with room to spare. For one typable term at a time second-order arithmetic is enough, because only the finitely many type expressions in its derivation are involved.

Part IV · More rules

§18The price of a new rule

Uses §14 Derivable and true. Used by §19, §26, §33.

The claim that new typing rules are cheap to add can now be made exact, as one lemma. Three things make additions cheap.

  1. The collection of all type sets never changes. It was fixed in §5. A new form of type expression names more members of that collection and does not enlarge it. So ⋂ over all type sets, and with it ∀, means exactly what it meant before. No earlier lemma mentions the new construction.
  2. The theorem has one case per rule. A new rule is a new case. The old cases are untouched.
  3. The price is fixed. One lemma that the new set is a type set. One membership fact per rule. The addition lemma does the rest.

Definition · Addition

An addition is a new form of type expression, with a clause that says what it names, and zero or more new rules. The clause computes the set that the new form names under ρ from the sets that its parts name under ρ, by a fixed operation on sets, and from nothing else. A part under a bound variable X, as A in ∀X.A, contributes the function C ↦ ⟦A⟧ρ[X↦C] in the place of a set.

The clause for ∀X.A is of this form: its operation sends the function C ↦ ⟦A⟧ρ[X↦C] to the intersection of its values. So is the clause for A → B, with the arrow as the operation. A clause that looked at the type expression itself, and not only at what its parts name, would not be an addition.

Addition lemma · One lemma per additionhere, reviewed

Let an addition be given.

names
If the operation of the clause gives a type set for all inputs that are type sets, or functions from type sets to type sets, then Lemma N holds for the language with the new form.
rules
If, further, each new rule is true, then the soundness theorem, C1 (strong normalization) and C2 (consistency) hold for the system with the new rules.

So an addition costs one lemma, that the operation gives type sets, and one membership fact per rule, which is what makes the rule true. §19 pays the price in full for ∧, and the additions after it pay it in a few lines each. §26 and §33 extend the lemma to clauses whose parts are terms, and to parts of higher kind.

Proof

Names. Lemma N is proved by induction on type expressions, and the new form is one more case. N1 (type set): the parts name type sets, or functions from type sets to type sets, by the induction, so the operation gives a type set. N0 (free variables): what the parts name depends only on their free variables, by the induction, and the clause computes from that alone. N2 (substitution): A[B/X] replaces X inside the parts, and by the induction each part of A[B/X] names under ρ what the part of A names under ρ[X↦⟦B⟧ρ]; for a part under a bound variable Y, taken different from X and not free in B, N0 (free variables) keeps ⟦B⟧ the same under ρ[Y↦C], as in the ∀ case. The clause then gives the same set on both sides.

Rules. The soundness theorem is proved by induction on derivations, and each new rule is one more case, which holds because the rule is true. C1 (strong normalization) and C2 (consistency) use only the SN condition, the Base condition and M3 (smallest), which hold for every type set, so their proofs are unchanged; C2 also uses that a term derived in the empty context is closed, which holds as long as no new rule lets a free variable into the term except from the context, and none on this page does. ∎

The lemma that the operation gives type sets is where the weight lies. Narrow point 6 in §14 shows what goes wrong without it, and §23 says where it stops being cheap.

§19Intersection types

Uses §18 The price of a new rule. Used by §20, §21.

The first addition is the intersection of two type sets, with the name A ∧ B. It gets this section and the two after it, for three reasons. An argument that is used in two ways can be given a type expression for each use. ∧ is the finite form of ∀. And with ∧ the rules reach every strongly normalizing term, which the rules of System F do not.

Definition · The intersection of two type expressions

There is one more form of type expression: A ∧ B. An example is X ∧ (X → Y).

One clause is added:

⟦A ∧ B⟧ρ = ⟦A⟧ρ ∩ ⟦B⟧ρ

Two rules are added:

RuleFromConclude
∧ inΓ ⊢ t : A and Γ ⊢ t : BΓ ⊢ t : A ∧ B
∧ outΓ ⊢ t : A ∧ BΓ ⊢ t : A, and also Γ ⊢ t : B

System F with ∧ has the five rules of System F and these two rules.

System D has the five rules “variable”, “→ in”, “→ out”, “∧ in” and “∧ out”. Its type expressions are built from variables with → and ∧. It has no ∀. The name is Krivine’s.

For each of the two systems, a derivation uses the rules of that system, and “derivable” and “typable” are defined from derivations as in §13.

The term is the same above and below each of the two rules. A term with the type expression A ∧ B is not a pair of two terms. It is one term, and the rules give it A and also B.

A ∧ B names the intersection of two type sets, the two that A and B name. ∀X.A names an intersection over all type sets. So ∧ brings no new operation on sets. It is ∩ again, over two sets and not over all of them.

Lemma · The intersection of two type setshere, reviewed

Let T and U be type sets.

∧ in

∧ out
If t ∈ T ∩ U, then t ∈ T and t ∈ U.

So, by the addition lemma of §18, Lemma N, the soundness theorem and both corollaries hold for System F with ∧.

The soundness theorem and C1 (strong normalization) hold for System D, because a derivation of System D is a derivation of System F with ∧. System D has no ∀, and C2 (consistency) reads there: no closed term t has ⊢ t : X for a variable X.

Proof

Type set. This is the intersection lemma of §8, with the index set {1, 2} and F(1) = T, F(2) = U.

∧ in and ∧ out are the definition of ∩.

The addition lemma. The clause computes ⟦A ∧ B⟧ρ from the two sets that its parts name, by ∩, which gives a type set by the first part. So Lemma N holds. The two rules are true: fix ρ, and replace the variables of the context by members of the type sets that their type expressions name. If the term that results is in ⟦A⟧ρ and in ⟦B⟧ρ, then it is in ⟦A ∧ B⟧ρ, which is “∧ in”; if it is in ⟦A ∧ B⟧ρ, then it is in both, which is “∧ out”.

C2 in System D. Send X to Min. A closed term t with ⊢ t : X would be a closed member of Min, and by M3 (smallest) there is none. ∎

Example · The intersection of no type sets is not a type set

Many presentations of intersection types have one more type expression, ω, with the rule that Γ ⊢ t : ω for every Γ and every t. It stands for the intersection of no type expressions.

Quoted from the literature: with ω and its rule, a term is weakly normalizing if and only if it is typable in such a way that ω does not occur in the context or in the type expression of the term.

Lemma · Laws of ∩ on type setshere, reviewed

Let T, U and V be type sets, and let F give a type set F(C) for each type set C.

repeat
T ∩ T = T. In standard terms, ∩ is idempotent. This is true of any set, and it is listed because the remark at the end of this section is about systems that give it up.
same input
(T ⇒ U) ∩ (T ⇒ V) = T ⇒ (U ∩ V).
same result
(T ⇒ V) ∩ (U ⇒ V) = (T ∪ U) ⇒ V. T ∪ U is a type set, by the union lemma of §8.
instances
⋂C F(C) ⊆ F(T) ∩ F(U). The intersection of two instances contains the intersection of all of them.
Proof

Repeat holds for any set.

Same input. A term t is in the left side if and only if, for every u ∈ T, t u ∈ U and t u ∈ V. That is the right side.

Same result. A term t is in the left side if and only if t u ∈ V for every u ∈ T and for every u ∈ U, that is, for every u ∈ T ∪ U.

Instances. This is instantiate, used at T and at U. ∎

Example · ∧ records which input goes to which result

I ∈ (TI ⇒ TI) ∩ (TK ⇒ TK), with the two hand-built type sets of §5. The term sends TI into TI, and TK into TK.

The arrow between the unions, (TI ∪ TK) ⇒ (TI ∪ TK), says less. It also contains λx.K, which sends every input to K. And λx.K is not in TI ⇒ TI: (λx.K) I →h K, and K ∉ TI.

Example · A law that is true and not derivable

By the law same input, the judgment x : (X→Y) ∧ (X→Z) ⊨ x : X → (Y ∧ Z) is true.

It is not derivable in System F with ∧. The term is a variable, so a derivation can use only the variable rule, the two ∧ rules and the two ∀ rules. Starting from (X→Y) ∧ (X→Z), these rules take it apart, put ∧ between the results, and add or remove a ∀ whose variable does not occur. An arrow into Y ∧ Z never appears.

The term λy.x y does get this type expression. With y : X added to the context, x y : Y and x y : Z are derivable, then “∧ in” gives x y : Y ∧ Z, and “→ in” gives λy.x y : X → (Y ∧ Z).

For this reason presentations of intersection types often add inclusions between type expressions as rules. That is subtyping, which §22 adds.

Remark · Intersection types that count uses

By the law repeat, A ∧ A names the same set as A. Some systems keep A ∧ A and A apart: a variable with A ∧ A is then used exactly twice, once for each part. They are called non-idempotent intersection types.

Quoted from Bernadet and Graham-Lengrand: in such a system a derivation gets strictly smaller with every step of the term. So strong normalization follows by counting, “without requiring reducibility techniques”, which are the techniques of this page. The size of a derivation also bounds the length of the longest run.

The semantics of this page cannot express this. A set does not record how many times a member is used.

§21With ∧, every strongly normalizing term is typable

Uses §3 SN is generated by three rules, §19 Intersection types. No later section uses it.

In System F the soundness theorem has no converse, even for typability alone: some strongly normalizing terms are not typable, as quoted in §14. With ∧ that changes.

Characterization theorem · Which terms are typable with ∧known, proof here

For every term t, the following three statements are equivalent.

SN
t is strongly normalizing.
D
t is typable in System D.
F with ∧
t is typable in System F with ∧.

So the set of terms that are typable in System D is SN, the largest type set.

The theorem is a known result, and so is the route of the proof, induction on the three rules of the generation lemma. The text of the proof is this page’s.

Proof

From D to F with ∧. A derivation of System D is a derivation of System F with ∧.

From F with ∧ to SN. This is C1 (strong normalization) for System F with ∧.

From SN to D. By the generation lemma of §3, it is enough to show that the set of terms that are typable in System D is closed under the three rules of that lemma. The proof uses three standard facts about the derivations of System D. Each is proved by a routine induction on the derivation, which is omitted.

  • More variables. If Γ ⊢ t : A, and Δ contains every x:B of Γ, in any order, then Δ ⊢ t : A.
  • Fewer variables. If Γ ⊢ t : A, and y is not free in t, then Γ without y also derives t : A.
  • Stronger variables. If Γ ⊢ t : A, and Δ is Γ with one x:B replaced by x : B ∧ C or by x : C ∧ B, then Δ ⊢ t : A.

For two contexts Γ and Γ′, write Γ ∧ Γ′ for a context that has the variables of both. A variable with B in Γ and B′ in Γ′ has B ∧ B′ in it. By more variables and stronger variables, every judgment that Γ derives, and every judgment that Γ′ derives, Γ ∧ Γ′ derives too.

Variable applied. Let Γi ⊢ ui : Ai for each i. Let Γ be Γ1 ∧ … ∧ Γn joined in the same way with the context x : A1 → … → An → Y. Then Γ ⊢ x : A1 → … → An → Y and Γ ⊢ ui : Ai, and n uses of “→ out” give Γ ⊢ x u1…un : Y.

Abstraction. Let Γ ⊢ t : B. If x is not in Γ, add x : X. Move x : A to the end of the context. Then “→ in” gives λx.t the type expression A → B.

Head step, without trailing arguments. Let Γ ⊢ t[u/x] : A and Γ′ ⊢ u : B, with x chosen so that it is not in Γ, not in Γ′ and not free in u. The claim is that there is a type expression B′ with

Γ ∧ Γ′ ⊢ u : B′  and  Γ ∧ Γ′, x:B′ ⊢ t : A

Then “→ in” and “→ out” give Γ ∧ Γ′ ⊢ (λx.t) u : A. The claim is proved by induction on the derivation of Γ ⊢ t[u/x] : A, for all Γ, t and A at once.

  • If t is x, then t[u/x] is u. Take B′ = A.
  • If x is not free in t, then t[u/x] is t. Take B′ = B. This is the only place where the proof uses that u is typable.
  • Otherwise t is an application or an abstraction, and the last rule of the derivation is not the variable rule.
    • “∧ in”, with A = A1 ∧ A2. The induction gives B1 for A1 and B2 for A2. Take B′ = B1 ∧ B2.
    • “∧ out”. The induction gives a B′ for the judgment above the rule, and the same B′ serves.
    • “→ out”, with t = t1 t2. The induction gives B1 for t1 and B2 for t2. Take B′ = B1 ∧ B2.
    • “→ in”, with t = λy.t1 and y chosen so that it is not in Γ′ and not free in u. The judgment above the rule is Γ, y:A1 ⊢ t1[u/x] : A2. The induction gives a B′, with u : B′ derived in a context that contains y. Fewer variables removes y from that context. Then “→ in” gives λy.t1 its type expression.

Where two type expressions B1 and B2 are replaced by B1 ∧ B2, “∧ in” gives u : B1 ∧ B2, and stronger variables keeps the judgments about t derivable.

Head step, with trailing arguments. Let Γ ⊢ t[u/x] u1…un : C with n ≥ 1, and Γ′ ⊢ u : B. The claim is that Γ ∧ Γ′ ⊢ (λx.t) u u1…un : C. It is proved by induction on the derivation. If the last rule is “∧ in” or “∧ out”, the induction applies to the judgments above it, which are about the same term. Otherwise the last rule is “→ out”, from Γ ⊢ t[u/x] u1…un−1 : A′ → C and Γ ⊢ un : A′. By induction, or by the case without trailing arguments if n = 1, Γ ∧ Γ′ ⊢ (λx.t) u u1…un−1 : A′ → C. Then “→ out” gives the claim. ∎

The proof needs ∧ wherever one thing has to serve several uses. There are two such places. If two contexts are joined, then a variable that both contain gets both type expressions. And if a head step is undone, then the copies of the argument u inside t[u/x] may have received different type expressions B1,…,Bk, one for each copy. Before the step there is one u, and it gets B1 ∧ … ∧ Bk. The example with δ I in §19 shows this for two copies.

If there is no copy, because the head step threw u away, then the derivation for t[u/x] says nothing about u, and u has to be typable by assumption. This is the safe head step of §2 again, with “typable” in the place of “in SN”. So the proof follows the definition of a type set: its case “variable applied” matches the Base condition, and its case “head step” matches the closure condition.

Example · The discarded argument has to be typable

The head step (λx.y) (I I) →h y discards its argument. A derivation in System D for the term before the step:

LineJudgmentRule

2y : X ⊢ λx.y : (Y→Y) → X→ in, from 1

The derivation for y alone is line 1 without x. It says nothing about I I, and lines 3 to 5 have to be supplied from the assumption that the argument is typable. In the proof this is the case “x is not free in t”, with Γ′ empty and B′ = Y→Y; there, more variables is what moves ⊢ I I : Y→Y under the context y : X, which the example avoids by deriving lines 3 to 5 under y : X directly. With Ω in the place of I I there would be no line 5, and (λx.y) Ω is indeed not in SN.

Three things the theorem does not say.

  • It is about typability, NOT about every true judgment. It says that a strongly normalizing term has some type expression in some context. It does not say that every true judgment is derivable. The lemma “True and not derivable” of §14 still holds with ∧, and so does the law that is true and not derivable, in §20.
  • It does not make System F easier. System D has no ∀, so its soundness needs no intersection over all type sets, and the impredicative definition of narrow point 5 does not occur. To get the strong normalization of System F from System D, one would have to show that every term that is typable in System F is typable in System D. By the theorem, that is the same as showing that it is strongly normalizing.
  • It gives no way to find a derivation. No program decides whether a term is strongly normalizing. That is a standard fact, quoted here. So, by the theorem, no program decides whether a term is typable in System D. A derivation that is given can still be checked line by line.

§22Subtyping, least fixed points, existential types

Uses §18 The price of a new rule, §20 Laws of the intersection. Used by §23, §27.

Three more additions follow, each at the price that the addition lemma of §18 states. Each is given by its set, by the lemma that the set is a type set, and by its membership facts. The form of type expression, the clause and the rules are then read off, as §19 did for ∧, and the addition lemma gives Lemma N, the soundness theorem and both corollaries for the system with the new rules.

Addition · Subtyping

Set
No new set. The relation T ⊆ T′ between type sets.
Lemma
Nothing to check.
Facts
If t ∈ T and T ⊆ T′ then t ∈ T′. Inclusions come from true facts: Min ⊆ T ⊆ SN; if T′ ⊆ T and U ⊆ U′ then T ⇒ U ⊆ T′ ⇒ U′; ⋂C F(C) ⊆ F(D); and the laws of ∩ in §20.

Example · Subtyping

ID ⊆ ID ⇒ ID, by the fact ⋂C F(C) ⊆ F(D), with D = ID. So the self-application example reads: pass to a larger type set, then apply.

Example · A bigger input gives a smaller arrow

A smaller input set gives a larger arrow, so SN ⇒ SN ⊆ TI ⇒ SN, because TI ⊆ SN. The inclusion is strict: δ is in TI ⇒ SN and not in SN ⇒ SN. With fewer inputs to handle, more terms qualify. In standard terms, the arrow is contravariant in its first argument.

Why δ ∈ TI ⇒ SN: take u ∈ TI. Its head steps lead to I or to a variable applied to arguments. I u ∈ SN because u ∈ SN, and a variable applied to strongly normalizing arguments is in SN by R2 (variable applied). R3 (safe head step) carries this back along the head steps, so u u ∈ SN, and then δ u ∈ SN.

Addition · Least fixed points

Set
For a function F from type sets to type sets, μF is the intersection of all type sets C with F(C) ⊆ C. F is monotone if the following holds: if C ⊆ C′ then F(C) ⊆ F(C′).
Lemma
μF is a type set for every F, as an intersection of a nonempty collection: SN is in the collection, since F(SN) ⊆ SN. If F is monotone, then F(μF) = μF. For every C in the collection F(μF) ⊆ F(C) ⊆ C, so F(μF) ⊆ μF. Then F(F(μF)) ⊆ F(μF), so F(μF) is in the collection and μF ⊆ F(μF). This is the Knaster–Tarski theorem.
Facts
For monotone F: t ∈ μF if and only if t ∈ F(μF), with the term unchanged. Induction: if F(C) ⊆ C then μF ⊆ C. The rules carry the side condition that F is monotone, which the usual presentations state as “X occurs positively in A”; without it the two rules are false, because μF is still a type set but need not be a fixed point.

Example · Least fixed points

Numbers that carry their predecessor. Let F(C) = ⋂D (D ⇒ ((C ⇒ D) ⇒ D)). It is monotone, because C sits to the left of two arrows. Zero is λz.λs.z, which is in F(C) for every C. If n ∈ μF then its successor λz.λs.s n is in F(μF) = μF.

Addition · Existential types

Set
⋃C F(C), the terms that are in F(C) for at least one type set C.
Lemma
It is a type set. It is the union of a nonempty collection of type sets, so the union lemma of §8 applies.
Facts
If t ∈ F(D) then t ∈ ⋃C F(C). To use a member t: if s[v/x] ∈ U for every type set C and every v ∈ F(C), then s[t/x] ∈ U.
Caution
Only the length of the proof depends on the conditions chosen in §5. For type sets, closure under union is the union lemma, which takes one line. For Girard’s reducibility candidates, which §35 compares, the union of candidates is also a candidate, by a proof given there, together with the history of the question.

δ ∈ ⋃C (C ⇒ C), with C = ID, although δ ∉ ⋂C (C ⇒ C). The term sends some type set into itself, and not every type set.

§23Limits of adding rules

Uses §22 Subtyping, least fixed points, existential types. Used by §30, §41.

“One lemma per addition” is true, and the lemma is not a formality. There are four limits.

Limit 1 · True rules about the wrong set are worthless

Try
Add a name for a set that is not a type set, together with rules that are true of that set.
Breaks
Narrow point 6 did this with Empty, a name for ∅, and typed the looping term λx.Ω.
Lesson
The lemma “the new set is a type set” carries the weight, and it is not a formality. A type set for “false” can be no smaller than Min, which has no closed member and still contains the variables.

Limit 2 · Some sets do not exist

Try
A type set T with T = T ⇒ T, so that every untyped term is typable.
Breaks
For such a T, any u ∈ T is also in T ⇒ T, so u u ∈ T, so δ ∈ T ⇒ T = T by abstract. Then δ δ ∈ T, against the SN condition.
Lesson
No type set satisfies the equation. Fixed points exist for monotone F, as §22 shows, and C ⇒ C is not monotone in C.

Limit 3 · Only strong normalization is certified

Try
Read t ∈ T as all that typing usually promises, including that t stays in T while it runs.
Breaks
Take T = Gen({I I}) from §5. I I ∈ T and I I → I, but I ∉ T.
Lesson
Type sets are closed under undoing safe head steps. They are not closed under steps. The statement “if t : A and t → t′ then t′ : A”, called subject reduction, is known to hold for plain System F, by a separate proof about derivations. It is known to fail for the rule that uses a member of an existential type, in §22.

Limit 4 · New forms of terms reopen the definition

Try
Add pairs with projections, or built-in numbers with a recursor, as a few more rules.
Breaks
The Base condition and the closure condition list forms of terms: a variable applied to arguments, an abstraction applied to arguments. With pairs, fst x is a new form with no head step, and fst ⟨t,u⟩ → t is a new head step that throws u away. Narrow point 3 comes back for it.
Lesson
Lemma R and the three conditions have to be restated for the new terms, and §8 checked again. It is the same work as in §5 and §8, and no harder. But it is the definition again, and not one more lemma on top of it.

One more observation on cost. Every intersection over all type sets uses the same strong principle as narrow point 5. The additions do not need more than that.

§24Families of type sets

Uses §8 Arrow, intersection and union, §9 Four facts. Used by §25, §27, §34.

Some type sets vary with a term. Such a varying type set is called a family. The dependent arrow, self types and the dependent intersection are built from families.

Definition · Family

A function from terms to type sets is a function V that gives a type set V(u) for every term u.

Two terms are convertible if they are joined by steps, taken in either direction.

A family is a function from terms to type sets that is constant along steps: if u → u′ then V(u) = V(u′). So a family gives convertible terms the same type set.

For a function F that gives a type set for each family, ⋂V F(V) is the intersection indexed by the set of all families, in the sense of §8: the terms that are in F(V) for every family V.

The set of all families is not empty, because the constant functions are families. So ⋂V F(V) is a type set by the intersection lemma of §8, and generalize and instantiate of §9 hold for it. Like the intersection over all type sets, this intersection is impredicative.

Remark · Two modeling choices, and what each costs

A family is defined on all terms, and not only on the members of some type set. The reason is that the self type of §27 and the dependent intersection of §28 apply V to the very term that is being tested, which may be any strongly normalizing term. So V has to be defined on all of SN at least, and defining it on all terms costs nothing more. The price is that no rule says which type expressions are well formed: in P t of §26, the term t may be any term. The usual presentations give P a domain, and §27 reports what that changes in System S.

A family is constant along steps. Each construction built from a function from terms to type sets asks something of that function, and the list is this. The dependent arrow of §25 and the intersection over the members of a type set in §29 ask nothing. The self type of §27 and the dependent intersection of §28 ask that the function is constant along safe head steps. The rule of term conversion in §26 asks that it is constant along all steps, so that a term inside a type expression can be run without changing what the type expression names; and so does the rule “∀ out, for families” there, because the function w ↦ ⟦B⟧ρ[x↦w] that it instantiates at is constant along steps of w only if every family is constant along all steps, as the proof of N4 (term steps) shows. The page asks the strongest of the three of every family, so that one notion serves every construction. The price is that ∀P ranges over fewer functions than it otherwise could, and the example “A function that is not a family” shows one that is excluded; EQ(u, v) of §25 is weaker by the same amount. Each lemma that follows states which of the three it needs.

Definition · The family Vv

For a term v, Vv is the function that gives SN at every term convertible with v, and Min at every other term.

A step does not change which terms a term is convertible with, so Vv is a family. It tells the terms convertible with v apart from all others, and §25 and §30 check other families against it.

Example · VI

VI(I I) = SN, because I I → I. VI(K) = Min, because K and I are not convertible. That rests on the Church–Rosser theorem, quoted here and not proved: two different normal forms are never convertible.

Example · A function that is not a family

Let V(u) be SN if u is the term I itself, and Min otherwise. Every value is a type set. But I I → I, and V(I I) = Min while V(I) = SN. So V is not constant along steps, and it is not a family. §26 shows which rule would be false if it were one.

Example · A family that no program can decide

Let W(u) be SN if u has a normal form, and Min otherwise. It is a family: if u → u′ and u has a normal form n, then u′ reaches n too, by the Church–Rosser theorem; and if u′ has a normal form, then so does u, through u′. No program decides whether a term has a normal form, which is a standard fact, quoted. So ∀P ranges over families that no program could pick out. It also ranges over families that no type expression names, by the counting of §11: the constant families alone are as many as the type sets, uncountably many, and there are countably many type expressions.

§25The dependent arrow and equality

Uses §9 Four facts, §24 Families of type sets. Used by §26.

The arrow T ⇒ U sends every member of T into one type set U. With a family in the place of U, the type set that the result lands in can depend on the argument.

Definition · Dependent arrow

For a type set T and a function V from terms to type sets, the dependent arrow is

Πu∈T V(u) = { t : t u ∈ V(u) for every u ∈ T }

If V is the constant function V(u) = U, then the dependent arrow is T ⇒ U.

Lemma · The dependent arrow is a type sethere, reviewed

If T is a type set and V is any function from terms to type sets, then Πu∈T V(u) is a type set. Nothing is asked of V along steps.

Proof

The proof of the arrow lemma goes through with V(v) in the place of U, where v is the argument at hand: in each of the three conditions the argument is fixed before U is used. ∎

The four facts of §9 carry over. Apply and abstract hold for the dependent arrow. If t ∈ Πu∈T V(u) and u ∈ T, then t u ∈ V(u). If t[u/x] ∈ V(u) for every u ∈ T, then λx.t ∈ Πu∈T V(u). Generalize and instantiate hold for ⋂V F(V). There is a fifth fact, convert: if u and u′ are convertible, then a member of V(u) is a member of V(u′). It is the definition of a family.

Definition · EQ(u, v)

For terms u and v, EQ(u, v) = ⋂V (V(u) ⇒ V(v)).

A member turns a member of V(u) into a member of V(v), for every family V.

Example · Equality as a type set

  • If u and v are convertible, then V(u) = V(v) for every family, so I ∈ EQ(u, v). For instance I ∈ EQ(I I, I).
  • If u and v are not convertible, then EQ(u, v) has no closed member. Test with the family Vu of §24. A member is in SN ⇒ Min. If it were closed, then applied to I it would be a closed member of Min, and there is none. For instance EQ(I, K) has no closed member.

So EQ(u, v) has a closed member if and only if the two terms are convertible. It is a type set that says something about terms, and it is built from ⋂ and ⇒ alone.

Example · Equality is symmetric

Claim: λe.e I ∈ EQ(u, v) ⇒ EQ(v, u), for all terms u and v.

  1. Take any e ∈ EQ(u, v).
  2. The function W(w) = EQ(w, u) is a family, because a step of w changes no V(w).
  3. Instantiate with W: e ∈ W(u) ⇒ W(v), which is EQ(u, u) ⇒ EQ(v, u).
  4. Apply to I ∈ EQ(u, u): e I ∈ EQ(v, u).
  5. Abstract: λe.e I ∈ EQ(u, v) ⇒ EQ(v, u).

The instantiate line uses the intersection at a family that was itself defined by that intersection. This is the same self-reference as in the self-application example. Narrow point 5 in §11 says why it is allowed.

§26Dependent types: names and rules

Uses §13 The rules and the soundness theorem, §18 The price of a new rule, §25 The dependent arrow and equality. Used by §28, §30.

Type expressions can now contain terms. This section adds three forms of type expression, extends Lemma N and the addition lemma of §18 to terms inside type expressions, extends the definition of a true judgment, and adds five rules.

Definition · Type expressions that contain terms

A family variable P is a third sort of variable.

There are three more forms of type expression: P t, a family variable applied to a term; Πx:A.B, where the term variable x may be free in B; and ∀P.A.

On this page a family variable takes one term, and a type expression is never abstracted over a term. The price is paid in §43: the kinds of functions from terms, which the dependent corners of the λ-cube need in full, are only sketched there.

An assignment ρ now also gives a family ρ(P) for each family variable P and a term ρ(x) for each term variable x.

t[ρ] is t with each free variable x replaced by ρ(x), all at once.

u ≡ v is short for the type expression ∀P. P u → P v.

Three clauses are added:

⟦P t⟧ρ = ρ(P) at the term t[ρ]
⟦Πx:A.B⟧ρ = Πu∈⟦A⟧ρ ⟦B⟧ρ[x↦u]
⟦∀P.A⟧ρ = ⋂V ⟦A⟧ρ[P↦V]

A → B is now the case of Πx:A.B in which x is not free in B.

Example · A type expression for equality

The type expression u ≡ v names EQ(u[ρ], v[ρ]) of §25. The closed type expression I I ≡ I names EQ(I I, I), which contains I. The type expression Πx:X. x ≡ x names the terms that send every u ∈ ρ(X) into EQ(u, u), and λx.I is one of them.

Lemma N · Extended to terms inside type expressionshere, reviewed

N1
Type set. ⟦A⟧ρ is a type set.
N2
Substitution. ⟦B[u/x]⟧ρ = ⟦B⟧ρ[x↦u[ρ]]. Also ⟦A[P:=x.B]⟧ρ = ⟦A⟧ρ[P↦V]. Here A[P:=x.B] is A with every P t replaced by B[t/x], and V is the family w ↦ ⟦B⟧ρ[x↦w].
N4
Term steps. Running a term does not change what a type expression names. If a term inside A takes a step and the result is A′, then ⟦A⟧ρ = ⟦A′⟧ρ. If the term ρ(x) takes a step and the result is ρ′, then ⟦A⟧ρ = ⟦A⟧ρ′.
Proof

N0 (free variables) holds as stated, for all three sorts of variable.

N4 comes first, by induction on A. The case that matters is P t. A step of a term inside t, or of ρ(x), takes t[ρ] to the new term in zero or more steps, and ρ(P) is constant along steps, because it is a family. In every other case what the type expression names is computed from what the type expressions inside it name.

N1. By induction on A. P t names a value of a family. For Πx:A.B, the function u ↦ ⟦B⟧ρ[x↦u] gives type sets by induction, and the lemma on the dependent arrow in §25 asks nothing more of it. ∀P.A is an intersection over all families, which is a type set by §24.

N2. By induction, unfolding the clauses. In the equation for A[P:=x.B] the case P t reads ⟦B[t/x]⟧ρ = ⟦B⟧ρ[x↦t[ρ]] = V(t[ρ]), by the equation for B[u/x]. That V is a family, and not only a function from terms to type sets, is N4 (term steps). ∎

Addition lemma · Extended to parts that are termshere, reviewed

A part of an addition may now be a term t, which contributes the term t[ρ] to the clause, or a type expression B under a bound term variable x, which contributes the function w ↦ ⟦B⟧ρ[x↦w]. The addition lemma of §18 holds with one more hypothesis under names: the operation of the clause gives a type set for all inputs that are type sets, families and terms, and it is constant along steps of its term inputs. Then Lemma N holds with N4 (term steps) for the language with the new form.

Proof

As in §18, with one more case in the induction for N4 (term steps). A step of a term inside the new form, or of ρ(x), changes a term input of the operation by zero or more steps, which the operation does not see, by the new hypothesis; and it changes no other input, by the induction. The function w ↦ ⟦B⟧ρ[x↦w] is a family by N4 (term steps), so it is an input of the kind the hypothesis speaks of. For N2 (substitution) at a term part, the case uses that substituting a term and then applying ρ is the same as applying ρ with the substituted term: t[u/x][ρ] = t[ρ[x↦u[ρ]]], a fact about substitution and not about type expressions. The part rules is unchanged, with the definition of a true judgment of this section in the place of that of §12; the five rules of §13 stay true under it by their old proofs, the two rules for → being the cases of “Π in” and “Π out”. ∎

Definition · True judgment, with terms inside type expressions

A context may now be dependent: Ai may contain the earlier variables x1,…,xi−1, and A may contain all of them.

The judgment is true, written Γ ⊨ t : A, if the following holds: for every ρ such that ρ(xi) ∈ ⟦Ai⟧ρ for each i, and ρ(y) = y for every term variable y that is not in Γ, the term t[ρ] is in ⟦A⟧ρ.

If no type expression contains a term variable, then this is the definition of §12, with ui = ρ(xi). The clause ρ(y) = y says that a term variable outside Γ stands for itself. It is there so that a judgment speaks only about the variables that Γ declares, even when a type expression in Γ mentions another one, and so that C1 (strong normalization) can replace every variable by itself exactly as in §13.

Remark · What this treatment of dependent types covers

Where “constant along steps” is used. Two of the five rules of this section need families to be constant along all steps: term conversion, which is N4 (term steps) itself, and “∀ out, for families”, because the function w ↦ ⟦B⟧ρ[x↦w] that it instantiates at has to be a family, and the proof of N4 (term steps) makes it one only because every ρ(P) is constant along all steps. If families were asked less, that function could fail to be one: with B = P (y x), a safe head step of w is not a head step of y w. The dependent arrow needs nothing of its function, by §25. §24 lists what every construction on this page asks.

What is proved. Strong normalization for terms that carry no annotations, which is the price of Curry style named in §13. The usual presentations of dependent types put type expressions inside terms, and those type expressions contain terms again. Showing that everything there is strongly normalizing, annotations included, takes more bookkeeping, and this page does not do it. §43 comes back to this.

§27Self types

Uses §22 Subtyping, least fixed points, existential types, §24 Families of type sets. Used by §28.

Self types are one more addition, at the price that the addition lemma of §18 states. Their set is built from a family, and they are the first of three ways on this page to give a term a type expression that mentions the term itself; §28 and §29 give the other two.

Addition · Self types

Set
For a family V, the set ιx.V(x) = { t : t ∈ V(t) } is what Fu and Stump call a self type. A member is checked against the type set that it selects itself.
Lemma
It is a type set. Of V it uses only that V is constant along safe head steps, which every family is. The SN condition and the Base condition hold because each V(t) is a type set. For the closure condition, let s →h s′ be safe. If s′ ∈ V(s′), then s ∈ V(s′) by the closure condition, and V(s′) = V(s), because V is constant along the safe head step.
Facts
If t ∈ ιx.V(x) then t ∈ V(t), and if t ∈ V(t) then t ∈ ιx.V(x). These are the definition read both ways, and they are the two rules of Fu and Stump’s self types, without their premise that the type expression is well formed. That premise is the price: with it dropped, nothing here is something a machine could check, as §13 says of Curry style in general.

Example · Self types

Induction. With 0 = λs.λz.z and S = λn.λs.λz.s (n s z), combine this addition with the least fixed points of §22 to define Nat as the least type set satisfying

Nat = ιx. ⋂P ( StepP ⇒ (P(0) ⇒ P(x)) )
StepP = ⋂y∈Nat (P(y) ⇒ P(S y))

where P ranges over all families, and StepP is the intersection indexed by the members of Nat, in the sense of §8. The right-hand side is monotone in Nat: a larger Nat gives a smaller StepP, because the intersection has more members to satisfy, and a smaller StepP to the left of an arrow gives a larger set. So the least such type set exists. Then 0 ∈ Nat and S ∈ Nat ⇒ Nat. Every t ∈ Nat satisfies t s z ∈ P(t), for every family P, every s ∈ StepP and every z ∈ P(0). The type set of the result, P(t), mentions t itself. Without the self type it could not, and one would have iteration and not induction: a term applied t times, with no statement about t.

Remark · Why Fu and Stump moved away from self types

Quoted from their papers. In Fu and Stump’s System S every family variable is declared together with the terms it accepts, so the definition of Nat there declares P to accept the members of Nat, the type expression being defined, and it contains the terms 0 and S, which must be shown to be in Nat. The proof of strong normalization for System S erases every dependency on terms and proves Fω with type expressions defined in terms of themselves, replacing ιx.T by T. Stump’s later Calculus of Dependent Lambda Eliminations, the theory behind Cedille, replaces self types by three constructions: dependent intersections ιx:A.B, which §28 treats, implicit products, in §29, and an equality between terms, in §30. He states two reasons for leaving self types: the erasure method “is not applicable to analyze a system with large eliminations”, that is, with type expressions computed from terms; and the circularity was one “which System S avoided by using an ad-hoc form of mutually recursive types”.

Worked out for this page. The construction in the example meets neither difficulty, because it gives up what caused them. Here P ranges over the families on all terms. That collection is fixed before Nat is, so Nat occurs only in a place where the least fixed point of §22 applies. So this page gives a model for the two self-type rules and for this definition of Nat, and not a model of System S as a whole: in System S a family accepts only the terms it is declared for, and the rule of System S for such definitions appears to allow more than the monotone recursion of §22, which was not checked against the paper in detail.

As a set, a self type is the dependent intersection of §28 whose first part is SN: the set { t : t ∈ SN and t ∈ V(t) }.

§28The dependent intersection

Uses §19 Intersection types, §26 Dependent types: names and rules, §27 Self types. Used by §29.

Definition · Dependent intersection

For a type set T and a family V, the dependent intersection is the set { t : t ∈ T and t ∈ V(t) }.

There is one more form of type expression: ιx:A.B, where the term variable x may be free in B.

One clause is added:

⟦ιx:A.B⟧ρ = { t : t ∈ ⟦A⟧ρ and t ∈ ⟦B⟧ρ[x↦t] }

Two rules are added:

RuleFromConclude
ι inΓ ⊢ t : A and Γ ⊢ t : B[t/x]Γ ⊢ t : ιx:A.B
ι outΓ ⊢ t : ιx:A.BΓ ⊢ t : A, and also Γ ⊢ t : B[t/x]

The second part may mention the term itself. A ∧ B is the case in which x is not free in B. The form and its rules are Kopylov’s.

Lemma · The dependent intersection is a type sethere, reviewed

If T is a type set and V is a family, then { t : t ∈ T and t ∈ V(t) } is a type set. Of V the proof uses only that it is constant along safe head steps.

So, by the addition lemma of §18 as extended in §26, Lemma N holds with the new form of type expression, and with the two new rules the soundness theorem and both corollaries hold.

Proof

SN condition. The set is inside T.

Base condition. A member s of Base is in T and in V(s), because both are type sets.

Closure condition. Let s →h s′ be safe, with s′ ∈ T and s′ ∈ V(s′). Then s ∈ T, by the closure condition for T. Also s ∈ V(s′), by the closure condition for V(s′). And V(s′) = V(s), because V is constant along the safe head step. So s ∈ V(s).

The addition lemma. The clause computes the set from the type set that A names and the family w ↦ ⟦B⟧ρ[x↦w], by the dependent intersection, which gives a type set by the first part and has no term input. So the extended addition lemma gives Lemma N. The two rules are true: by N2 (substitution), ⟦B[t/x]⟧ρ = ⟦B⟧ρ[x↦t[ρ]], so t[ρ] is in ⟦A⟧ρ and in ⟦B[t/x]⟧ρ if and only if it is in ⟦ιx:A.B⟧ρ. ∎

Example · Two cases of the dependent intersection

  • If V is the constant family V(u) = U, then the dependent intersection is T ∩ U.
  • If T is SN, then it is { t : t ∈ V(t) }, because every V(t) is inside SN. That is the self type of §27.

So the dependent intersection contains both ∧ and the self type as cases. Stump’s Calculus of Dependent Lambda Eliminations has ιx:A.B in the place of self types, as the remark in §27 reports.

§29Implicit products

Uses §27 Self types, §28 The dependent intersection. Used by §31, §42.

Cedille is the system that Stump built after System S; its theory is the Calculus of Dependent Lambda Eliminations. It replaces self types by three constructions: the dependent intersection of §28, the implicit product of this section, and an equality between terms, in §30. The implicit product is due to Miquel. As a set, it is the intersection over the members of a type set.

Definition · Intersection over the members of a type set

For a type set T and a function V from terms to type sets, the intersection over the members of T, written ⋂u∈T V(u), is the intersection indexed by T in the sense of §8: the terms that are in V(u) for every u ∈ T.

T contains Base, so it is not empty, and the intersection is a type set by the intersection lemma of §8; generalize and instantiate of §9 hold for it. Nothing is asked of V along steps. Contrast with the dependent arrow of §25. A member t of Πu∈T V(u) is given u as an argument: t u ∈ V(u). A member t of ⋂u∈T V(u) is in V(u) without being given u.

Definition · The implicit product

There is one more form of type expression: ∀x:A.B, where the term variable x may be free in B. Cedille calls it an implicit product.

One clause is added:

⟦∀x:A.B⟧ρ = ⋂u∈⟦A⟧ρ ⟦B⟧ρ[x↦u]

Two rules are added:

RuleFromConclude
∀ in, for termsΓ, x:A ⊢ t : B, with x not free in tΓ ⊢ t : ∀x:A.B
∀ out, for termsΓ ⊢ t : ∀x:A.B and Γ ⊢ u : AΓ ⊢ t : B[u/x]

The term is the same above and below each rule, as it is for ∧ in §19. Contrast with “Π in” in §26: from Γ, x:A ⊢ t : B it concludes Γ ⊢ λx.t : Πx:A.B. The implicit rule drops the λ, and in return asks that t does not use x. In Cedille the term carries an abstraction Λx.t and an application t -u for these two rules; erasure removes both, and the rules above are what is left.

Lemma · The two rules for the implicit product are truehere, reviewed

The rules “∀ in, for terms” and “∀ out, for terms” are true. So, by the addition lemma of §18 as extended in §26, Lemma N, the soundness theorem and both corollaries hold with them added.

Proof

The addition lemma. The clause computes the set from the type set that A names and the family w ↦ ⟦B⟧ρ[x↦w], by the intersection over the members of the first, which is a type set by the definition’s note and has no term input.

∀ in, for terms. Fix ρ with ρ(xi) ∈ ⟦Ai⟧ρ for each variable of Γ. Take any u ∈ ⟦A⟧ρ and let ρ′ = ρ[x↦u]. The variables of Γ are still well placed under ρ′, because x is not free in their type expressions, by N0 (free variables). So the premise gives t[ρ′] ∈ ⟦B⟧ρ′. And t[ρ′] = t[ρ], because x is not free in t. So t[ρ] ∈ ⟦B⟧ρ[x↦u] for every u ∈ ⟦A⟧ρ, which is the clause.

∀ out, for terms. t[ρ] is in ⟦B⟧ρ[x↦u[ρ]] by instantiate, and that set is ⟦B[u/x]⟧ρ by N2 (substitution). ∎

Example · A term that works for every u without being told u

I ∈ ⋂u∈T (V(u) ⇒ V(u)) for every type set T and every family V, because I ∈ V(u) ⇒ V(u) for each u. So ⊢ I : ∀x:A. P x → P x is derivable, by the variable rule, “→ in” and “∀ in, for terms”. With the dependent arrow in the place of the implicit product, the term would have to be λx.I.

Example · Cedille’s natural numbers: induction with no recursive definition

Write cNat for the type set that ∀X.(X→X)→X→X names, with 0 = λs.λz.z and S = λn.λs.λz.s (n s z) as in §27. For a family P, let

StepP = ⋂y∈cNat (P(y) ⇒ P(S y))

which is an intersection over the members of cNat. Let V(w) = ⋂P ( StepP ⇒ (P(0) ⇒ P(w)) ), with P over all families, and let

Nat′ = { t : t ∈ cNat and t ∈ V(t) }

which is the dependent intersection of §28 with cNat as its first part. Then Nat′ is a type set, 0 ∈ Nat′, S ∈ Nat′ ⇒ Nat′, and every t ∈ Nat′ satisfies t s z ∈ P(t) for every family P, every s ∈ StepP and every z ∈ P(0). That is induction, and the type set of the result mentions t.

Contrast with the Nat of §27. There StepP was an intersection over the members of Nat itself, so Nat was defined in terms of itself and needed the least fixed point of §22. Here y ranges over cNat, which was fixed first, and no fixed point is needed. This is Stump’s construction, with the argument order of this page.

The implicit product is what makes it work. If StepP were the dependent arrow Πy∈cNat (P(y) ⇒ P(S y)), then a member s would take y as an argument, and S t s z, which runs to s (t s z), would hand s one argument where it expects two. Stump makes the same point about erasure: the step function must erase to the step of the Church numeral.

Proof

Type set. Each V(w) is a type set, by the arrow lemma and the intersection lemma of §8. V is constant along steps, because each P is. So V is a family, and the lemma of §28 applies.

0 ∈ Nat′. For 0 ∈ V(0), take any family P, s ∈ StepP and z ∈ P(0). Then 0 s z →h (λz.z) z →h z, and z ∈ P(0). Both head steps are safe, because s and z are in SN. So 0 s z ∈ P(0) by the closure condition, twice. The same two steps, with any type set C in the place of P(0) and any s ∈ C ⇒ C, give 0 ∈ cNat.

S ∈ Nat′ ⇒ Nat′. Take t ∈ Nat′. For any type set C, s ∈ C ⇒ C and z ∈ C, the term S t s z reaches s (t s z) by three safe head steps, and t s z ∈ C because t ∈ cNat; so S t ∈ cNat. For S t ∈ V(S t), take any P, s ∈ StepP and z ∈ P(0). Again S t s z reaches s (t s z) by three safe head steps. Now t ∈ V(t) gives t s z ∈ P(t). And t ∈ cNat, so instantiate gives s ∈ P(t) ⇒ P(S t). So s (t s z) ∈ P(S t), and S t s z ∈ P(S t) by the closure condition.

Induction is t ∈ V(t), read off. ∎

§30Equality and the Kleene trick

Uses §6 Why the definition is not simpler, §23 Limits of adding rules, §26 Dependent types: names and rules. Used by §39, §40, §42.

Cedille’s third construction is an equality between untyped terms, written {t ≃ t′}, with rules that use a proof of an equation without running it. §25 had equality as a defined type expression, u ≡ v, whose proofs are used by applying them. That difference decides which of Cedille’s rules fit.

Definition · The equality type set

For terms u and v, E(u, v) is SN if u and v are convertible, and Min otherwise.

There is one more form of type expression: {t ≃ t′}, for any terms t and t′.

One clause is added:

⟦{t ≃ t′}⟧ρ = E(t[ρ], t′[ρ])

The two values are forced by the rules below. A true equation needs a closed member, for the rule β, and SN is the type set that asks least of one. A false equation should prove anything, for the rule δ, so it has to name the smallest type set, which is Min by M3 (smallest).

Lemma · The equality type sethere, reviewed

type set
E(u, v) is a type set, and it is constant along steps of u and of v.
true equation
If u and v are convertible, then I ∈ E(u, v).
closed member
E(u, v) has a closed member if and only if u and v are convertible.

So, by the addition lemma of §18 as extended in §26, Lemma N holds with the new form of type expression: the clause computes the set from its two term inputs, and E is constant along their steps. On closed members, E(u, v) agrees with the EQ(u, v) of §25.

Proof

SN and Min are type sets, and a step does not change which terms a term is convertible with. I ∈ SN. SN has closed members and Min has none, by M3 (smallest). ∎

Cedille has five rules for the equality. They are quoted here from the paper on Cedille Core, with the terms erased, and with two changes: in Cedille, the proof β of a true equation may erase to any term at all, written β{s}, and here it erases to I; and Cedille’s convertibility includes the rule η, which §1 left out, so “convertible” here is the convertibility of §24, by β alone. The name “Kleene trick” is Stump’s, after Kleene’s realizability, which accepts any number as a realizer of a true equation. K′ stands for λx.λy.y.

Lemma · Three of the five rules are true, and two are nothere, reviewed

The rules β, ς and δ are true. The rules ρ and φ are not.

Proof

β is the fact true equation. ς holds because E(u, v) = E(v, u).

δ. K and K′ are distinct normal forms, so they are not convertible, by the Church–Rosser theorem, quoted. So ⟦{K ≃ K′}⟧ρ = Min, and Min is inside every type set, by M3 (smallest). So if e[ρ] ∈ Min, then e[ρ] ∈ ⟦B⟧ρ.

Why ρ and φ fail is limit 1 of §23 again. Each draws a conclusion from the existence of a member of {t ≃ t′}. In this semantics that existence says nothing, because the variables are members of every type set, and in particular of E(K, I) = Min. The rule δ draws its conclusion from Min itself, which is inside every type set, and that is why it is true. And a proof e of u ≡ v in §25 is used by applying it, e s ∈ P v, which is true even for e = y, because y s ∈ Base.

The rule φ fails for a second reason, which holds even for a true equation with a closed proof. It asks that if u ∈ T, and u and v are convertible, then v ∈ T: every type set would have to be closed under conversion. Not even SN is: (λz.I) Ω is convertible with I, by one step, and it is not in SN. Inside SN the same thing happens, as limit 3 of §23 shows: Gen({I I}) contains I I and not I.

With the rules β and φ added to those of §26, the judgment ⊢ (λz.I) Ω : ∀X.X→X is derivable. The term (λz.I) Ω is closed, and it is not in SN, because Ω can be run inside it forever. So C1 (strong normalization) is false for these rules, and no semantics that proves C1 can make both β and φ true.

Remark · What Stump’s semantics for Cedille does instead

Quoted. A type names a set of closed terms that is closed under conversion, and every closed term is allowed, “even non-normalizing ones”. The equality type {t ≃ t′} names the set of all closed terms if the two terms are convertible and the empty set otherwise. What is proved is consistency: no closed term has the type expression ∀X.X.

Measured against this page. Three differences, each of which answers one failure above.

  • No variables, so no Base condition and no limit 1. A context with a false equation has no instance, and a judgment under it is true for lack of instances. That is what makes ρ and φ true there.
  • Closed under conversion, so no limit 3. This is also why the terms cannot be restricted to SN: the arrow of two sets that are closed under conversion need not be closed under conversion inside SN. For example, λx.y and λx.(λz.y) (x x) are convertible, and λx.y ∈ SN ⇒ SN, but (λx.(λz.y) (x x)) δ runs to (λz.y) Ω, which is not in SN.
  • The empty set is allowed as the set that a type expression names. Narrow point 2 in §6 showed what that costs: ∅ ⇒ SN is the set of all terms, so membership says nothing about strong normalization. Stump’s semantics pays that price and gets consistency for it.

§31Inductive types three ways

Uses §22 Subtyping, least fixed points, existential types, §29 Implicit products. Used by §41.

The natural numbers have appeared three times: as the Church numerals cNat with induction in §29, as the least fixed point of §22 whose members carry their predecessor, and as the Nat of §27, which is the Church numerals again under a self type. This section puts the ways of building an inductive type side by side, adds a third in its general form, which is Mendler’s, and says what each costs in this semantics. The general form was chosen because Cedille uses it with good results, and the question was whether those results survive the move from Cedille’s rules to sets.

The Mendler-style fixed point

Definition · Mendler algebra, and the fixed point

Let F be any function from type sets to type sets. For a type set D, the Mendler algebras into D are

Alg(F, D) = ⋂C ((C ⇒ D) ⇒ (F(C) ⇒ D))

with C over all type sets, and the Mendler fixed point of F is

Fix(F) = ⋂D (Alg(F, D) ⇒ D)

The constructor is the term in = λu.λa. a (λr. r a) u.

A member of Alg(F, D) is one layer of a recursion: given a way c to handle a smaller thing of any type set C, it handles a thing of F(C). A member of Fix(F) runs any such layer. The name is Mendler’s, and the form is the one Firsov, Blair and Stump use in Cedille. Nothing is asked of F: not that it is monotone, and not that Fix(F) is a fixed point of it in any sense. The name “fixed point” is kept because it is the usual one.

Lemma · The Mendler fixed point, for any Fhere, reviewed

Let F be any function from type sets to type sets.

type set
Fix(F) is a type set, and so is Alg(F, D) for every type set D.
in
in ∈ F(Fix(F)) ⇒ Fix(F).
fold
If a ∈ Alg(F, D), then λz. z a ∈ Fix(F) ⇒ D, and (λz. z a) (in y) reaches a (λr. r a) y by three head steps: the layer a is run on y, with λr. r a as the way to handle a smaller thing.
Proof

Type set. Both are built from type sets by ⇒, by F, and by intersections indexed by the collection of all type sets. The arrow lemma and the intersection lemma of §8 apply.

in. Take u ∈ F(Fix(F)). It is to be shown that in u ∈ Fix(F): that for every type set D and every a ∈ Alg(F, D), in u a ∈ D. The term in u a reaches a (λr. r a) u by two head steps, both safe, because u and a are in SN. Instantiate a at C = Fix(F): a ∈ (Fix(F) ⇒ D) ⇒ (F(Fix(F)) ⇒ D). And λr. r a ∈ Fix(F) ⇒ D, by abstract: if r ∈ Fix(F), then instantiate r at D and apply to a, so r a ∈ D. So a (λr. r a) ∈ F(Fix(F)) ⇒ D, and a (λr. r a) u ∈ D. The closure condition, twice, gives in u a ∈ D.

Fold. If z ∈ Fix(F), then z a ∈ D by instantiate and apply, so λz. z a ∈ Fix(F) ⇒ D by abstract. The head steps are (λz. z a) (in y) →h in y a, then in y a →h (λa. a (λr. r a) y) a, then one step to a (λr. r a) y. ∎

The inductive part, for monotone F

Induction says more than fold: the result may mention the member itself, as in §27 and §29. For that the recursion layer must be allowed to assume the induction hypothesis for the smaller things, and “smaller” now has to mean “inside the inductive type”, not “of any type set”. The index set of the intersection shrinks accordingly.

Definition · Proof algebras, and the inductive part

Let F be a monotone function from type sets to type sets, in the sense of §22. For a type set C and a family Q, the proof algebras are

PrfAlg(C, Q) = ⋂D ⊆ C ( Πr∈D Q(r) ⇒ Πy∈F(D) Q(in y) )

an intersection indexed by the type sets D inside C, in the sense of §8; the index set contains Min, so it is not empty. Let

G(C) = { t : t ∈ Fix(F) and t ∈ ⋂Q (PrfAlg(C, Q) ⇒ Q(t)) }

with Q over all families, and let the inductive part Ind(F) be the least fixed point μG of §22.

A member of PrfAlg(C, Q) turns a proof of Q for every member of a type set D inside C into a proof of Q(in y) for every y ∈ F(D). G(C) is a dependent intersection of §28, whose second part is a family because each Q is.

Lemma · The inductive part, for monotone Fhere, reviewed

Let F be monotone.

type set
G is monotone, so Ind(F) = μG exists, is a type set, and equals G(Ind(F)). It is inside Fix(F).
in
in ∈ F(Ind(F)) ⇒ Ind(F).
induction
For every family Q and every p ∈ PrfAlg(Ind(F), Q): if e ∈ Ind(F), then e p ∈ Q(e). So λe. e p ∈ Πe∈Ind(F) Q(e).
out
Let out = λe. e (λf.λy.y). Then out ∈ Ind(F) ⇒ F(Ind(F)), and out (in u) reaches u by five head steps, however large u is.
Proof

Type set. If C ⊆ C′, then every D inside C is inside C′, so PrfAlg(C′, Q) ⊆ PrfAlg(C, Q), so PrfAlg(C, Q) ⇒ Q(t) ⊆ PrfAlg(C′, Q) ⇒ Q(t), because a smaller input set gives a larger arrow, and so G(C) ⊆ G(C′). Each G(C) is a type set by the lemmas of §8, §25 and §28. So μG exists and G(μG) = μG, by §22. It is inside Fix(F) by the definition of G.

Write V(t) for ⋂Q (PrfAlg(Ind(F), Q) ⇒ Q(t)), so that Ind(F) = { t : t ∈ Fix(F) and t ∈ V(t) }.

in. Take u ∈ F(Ind(F)). Since Ind(F) ⊆ Fix(F) and F is monotone, u ∈ F(Fix(F)), and in u ∈ Fix(F) by the lemma on the Mendler fixed point. For in u ∈ V(in u), take any family Q and p ∈ PrfAlg(Ind(F), Q). As before, in u p reaches p (λr. r p) u by two safe head steps. Instantiate p at D = Ind(F), which is inside itself: p ∈ Πr∈Ind(F) Q(r) ⇒ Πy∈F(Ind(F)) Q(in y). And λr. r p ∈ Πr∈Ind(F) Q(r), by abstract: if r ∈ Ind(F), then r ∈ V(r), so instantiate at Q and apply to p give r p ∈ Q(r). So p (λr. r p) u ∈ Q(in u), and the closure condition, twice, gives in u p ∈ Q(in u).

Induction. If e ∈ Ind(F), then e ∈ V(e), so e p ∈ Q(e) by instantiate and apply. Then abstract for the dependent arrow.

Out. Let Q be the constant family with value F(Ind(F)). Then λf.λy.y ∈ PrfAlg(Ind(F), Q): for any D inside Ind(F), any f ∈ Πr∈D F(Ind(F)) and any y ∈ F(D), the term (λf.λy.y) f y reaches y by two head steps, safe because f and y are in SN, and y ∈ F(D) ⊆ F(Ind(F)) because F is monotone. So by induction, e (λf.λy.y) ∈ F(Ind(F)) for every e ∈ Ind(F), and abstract gives out ∈ Ind(F) ⇒ F(Ind(F)). The head steps: out (in u) →h in u (λf.λy.y), then two steps to (λf.λy.y) (λr. r (λf.λy.y)) u, then two steps to u. ∎

Example · Mendler-style natural numbers

Let F(C) = ⋂D (D ⇒ ((C ⇒ D) ⇒ D)), the function of the example “Least fixed points” in §22: F(C) contains the zero λz.λs.z and, for each n ∈ C, the successor λz.λs.s n, which carries its predecessor. It is monotone. Then

0 = in (λz.λs.z)   S = λn. in (λz.λs.s n)   pred = λe. out e 0 (λm.m)

By the two lemmas, 0 ∈ Ind(F), S ∈ Ind(F) ⇒ Ind(F), and pred ∈ Ind(F) ⇒ Ind(F): out e is in F(Ind(F)), instantiate it at D = Ind(F), and apply to 0 and to λm.m ∈ Ind(F) ⇒ Ind(F). And pred (S n) reaches n by ten head steps, whatever n is: one for pred, one for out, one that takes S n to in (λz.λs.s n), four for in and λf.λy.y, two that apply λz.λs.s n to 0 and to λm.m, and one for (λm.m) n. Induction holds with PrfAlg(Ind(F), Q) as the induction step: a member must give Q(in y) for every y ∈ F(D), among them the zero and the successors of members r ∈ D, from a proof of Q(r) for every r ∈ D.

The Church numerals of §29 have no such predecessor: there, as Firsov, Blair and Stump report, citing Parigot, computing the predecessor takes a number of steps that grows with the number. That is the reason Cedille uses this encoding. The claims about the Church numerals are quoted and not proved here.

Remark · What Cedille’s casts do, and what replaces them here

Quoted. In Cedille the inductive part is built without a fixed point. Its proof algebras quantify over every type R together with a cast from R to the fixed point, a function that is provably equal to the identity; so its inductive part is, in the terms of this section, G(Fix(F)). Its induction principle for proof algebras over the inductive part itself is then derived by using the induction hypothesis for the members of R to build a cast from R into the inductive part. A cast is applied by introducing a dependent intersection [x, y {p}] whose two parts are joined by a proof p that the cast is the identity, and projecting; Cedille Core, from which §30 takes its rules, replaced that annotation by the rule φ, which does the same retyping. Firsov, Blair and Stump also replace functoriality of F by an identity mapping, which lifts casts to casts.

Worked out for this page. Here a cast between type sets is an inclusion D ⊆ C, and it appears as a condition on the index set of the intersection, not as a hypothesis, because §30 showed that φ is false in this semantics and limit 1 of §23 says why a hypothesis cannot carry it. An identity mapping becomes the condition that F is monotone, which is what in, induction and out use. G(Fix(F)), Cedille’s inductive part, has in and induction for proof algebras over Fix(F) by the same proof, with no fixed point. What it lacks is the passage to proof algebras over the inductive part itself, which is the step Cedille makes by building a cast from the induction hypothesis; and it is that passage that out needs, since λf.λy.y is a proof algebra over Ind(F) and not over Fix(F). The least fixed point is what replaces the cast. Ind(F) is inside G(Fix(F)), because G is monotone and Ind(F) = G(Ind(F)) with Ind(F) ⊆ Fix(F); whether the two are the same type set was not settled for this page. The obstacle is the one of §40: the induction principle of G(Fix(F)) quantifies over proof algebras p, and a p with a free variable at its head passes every requirement, so nothing about a member of G(Fix(F)) can be read off from the principle alone. The Mendler fixed point Fix(F) itself, its constructor and fold cost nothing and ask nothing of F, which is one of the points Firsov, Blair and Stump make, and it survives the move from rules to sets.

Part VI · System Fω

§32Kinds

Uses §9 Four facts. Used by §33.

System Fω has type expressions that name functions on type sets, such as λX:∗. X → X. Its semantics needs one more notion, and it is a light one.

Definition · Kind

Write Ty for the collection of all type sets of §5.

The kinds are these sets:

∗
the set Ty itself;
κ → κ′
the set of all functions from the kind κ to the kind κ′.

Every kind is a nonempty set. For a kind κ and a function H from κ to Ty, ⋂c∈κ H(c) is the intersection indexed by κ, in the sense of §8: the terms that are in H(c) for every c ∈ κ.

This is a modeling choice: a kind is a plain set, with nothing like the three conditions of §5. Those conditions exist because terms are run. The members of kinds are sets and functions on sets, and nothing at this level is run. The price is paid in the metatheory, and §33 names it. §34 gives the other reading of kinds, as sets of type expressions with the three conditions, and says which question each reading answers.

Example · Members of the kind ∗ → ∗

Every function from type sets to type sets is a member, however it is given:

  • C ↦ C ⇒ (TK ⇒ C), which uses a hand-built type set as a fixed ingredient;
  • C ↦ C ⇒ C, and the constant function C ↦ SN;
  • the function that gives SN if I ∈ C and Min otherwise.

The page has used members of this kind since the definition of ⋂C F(C), where F was any function from type sets to type sets. As with type sets, there are far more members than type expressions to name them.

One kind further up, the function F ↦ ⋂C F(C) is a member of (∗ → ∗) → ∗. So intersection over all type sets is itself a member of a kind.

Example · An intersection over a kind

⋂F∈∗→∗ ⋂C (F(C) ⇒ F(C)) is a type set. It contains I, because I ∈ T ⇒ T for every type set T, and each F(C) is a type set. The function that gives SN if I ∈ C and Min otherwise is one of the F it is tested against.

No new lemma is needed. ⋂c∈κ H(c) is an intersection indexed by a nonempty set, so it is a type set by the intersection lemma of §8, and generalize and instantiate of §9 hold for it.

§33System Fω: names and rules

Uses §13 The rules and the soundness theorem, §18 The price of a new rule, §32 Kinds. Used by §34, §39, §41, §42.

Definition · Type expressions of higher kind

Fω has three more forms of type expression: an abstraction λX:κ.A, an application A B, and ∀X:κ.A for any kind κ.

A well-formed type expression has a kind, written A : κ. The rules are the usual ones:

  • Each variable X comes with a kind.
  • If A : κ′, then λX:κ.A : κ → κ′.
  • If A : κ → κ′ and B : κ, then A B : κ′.
  • If A : ∗ and B : ∗, then A → B : ∗.
  • If A : ∗, then ∀X:κ.A : ∗.

A step of a type expression rewrites a type expression (λX:κ.A) B inside it to A[B/X].

The symbols ∗ and κ → κ′ are written inside type expressions here. There they are names for the kinds of §32.

An assignment ρ now sends each variable to a member of its kind, and three clauses are added:

⟦λX:κ.A⟧ρ = the function c ↦ ⟦A⟧ρ[X↦c]
⟦A B⟧ρ = ⟦A⟧ρ applied to ⟦B⟧ρ
⟦∀X:κ.A⟧ρ = ⋂c∈κ ⟦A⟧ρ[X↦c]

Example · A type expression that names a function

λX:∗. X → X names the function C ↦ C ⇒ C, a member of ∗ → ∗. λX:∗. X → Y has a free variable. With ρ(Y) = SN it names C ↦ C ⇒ SN, and another assignment gives another function.

Example · Two type expressions, one set

(λX:∗. X → X) (∀Y:∗. Y → Y) names the function C ↦ C ⇒ C applied to ID, which is ID ⇒ ID. The type expression (∀Y:∗. Y → Y) → (∀Y:∗. Y → Y) names the same set. The two differ by one step inside the type expression.

Example · Quantifying over a function on type sets

∀F:∗→∗. ∀X:∗. F X → F X names the intersection over a kind from §32. So I is in it.

Lemma N · Extended to kindstextbook

N1
Member of its kind. If A : κ, then ⟦A⟧ρ is a member of κ.
N2
Substitution. ⟦A[B/X]⟧ρ = ⟦A⟧ρ[X↦⟦B⟧ρ].
N3
Type steps. (λX:κ.A) B and A[B/X] name the same thing. So do any two type expressions joined by such steps.
Proof

N1 is by induction on the rules that give A its kind. An abstraction names a function into the right kind. An application applies a function to a member of its domain. The ∀ case is the intersection lemma. N2 is by induction on A.

N3. By the clauses for λ and for application, (λX:κ.A) B names ⟦A⟧ρ[X↦⟦B⟧ρ]. By N2 (substitution) that is ⟦A[B/X]⟧ρ. A step inside a larger type expression changes nothing either, because what a type expression names is computed from what the type expressions inside it name. ∎

Addition lemma · Extended to parts of higher kindhere, reviewed

A part of an addition may now name a member of any kind. The addition lemma of §18 holds with its hypothesis read for kinds, that the operation of the clause gives a member of the form’s kind for all inputs that are members of their kinds, and with N1 read as “member of its kind” and N3 (type steps) added to its conclusion: a step inside a part changes nothing, because the clause computes from what the parts name, and by N3 that is unchanged.

Theorem · The rules that changetextbook

The theorem and both corollaries hold for System Fω. Its two ∀ rules carry a kind, and there is one new rule.

RuleFromConclude
∀ inΓ ⊢ t : A, with X not free in ΓΓ ⊢ t : ∀X:κ.A

Every type expression in a judgment has the kind ∗. The rule of conversion also needs that a step takes a well-formed type expression of kind κ to a well-formed type expression of the same kind, so that B names a member of ∗. That is subject reduction for the kinding rules, which are the rules of the simply typed λ-calculus one level up; it is a textbook fact, quoted here and not proved.

Proof

∀ in and ∀ out are generalize and instantiate over the kind κ. Instantiate is used at ⟦B⟧ρ, which is a member of κ by N1 (member of its kind). Conversion holds because A and B name the same set, by N3 (type steps). The corollaries use the SN condition and the Base condition exactly as they do for System F. ∎

Remark · What was not needed

The proof never asks whether type expressions are strongly normalizing under their own steps. The set that a type expression names is defined by recursion on the type expression, so it exists either way. That they are strongly normalizing is a separate fact and an easier one. The type expressions of Fω form a simply typed λ-calculus, in which the kinds play the role of type expressions, and that is the case Tait’s method was made for, the one in Harper’s note of §45. It matters for checking derivations by machine, and not for C1 (strong normalization).

The cost is in the metatheory, the theory in which this proof is carried out. Each level of kinds needs the set of all functions on the level below, which amounts to one more power set.

§34New kinds, and the kind of all kinds

Uses §24 Families of type sets, §33 System Fω: names and rules. Used by §43.

Addition · New kinds

At the level of kinds an addition costs even less. A kind has no conditions to satisfy. It only has to be a nonempty set, and then intersection over it is a type set, by the intersection lemma of §8. Any nonempty set of members of a kind is a kind, for instance the type sets below a given one, which gives bounded quantification, or the monotone functions on type sets. Two new kinds matter for what follows.

Terms
The families of §24: functions from terms to type sets that do not change along steps. With this kind a type set may depend on a term. This is what the Calculus of Constructions adds to Fω, and §43 sketches it.
Levels
The kinds built so far form a set, so that set can be a kind of the next level. It gives quantifying over kinds, one level down.

The one collection that is not a set is that of all kinds of every level. Narrow point 7 is about it.

Narrow point 7 · A kind of all kinds

Goal
Give kinds the power that ∀ gives type expressions.
Try
Let kinds quantify over kinds, the way ∀ quantifies over type sets: allow the kind “for every kind k, H(k)”, where H turns kinds into kinds. As syntax, this is a kind ∀k.κ with a variable k for kinds inside κ, and it is the rule that System U⁻ adds to Fω. In the semantics it needs the collection Kinds of all kinds to be a set that is closed under function sets and contains every product ∏k∈Kinds H(k). A member of that product picks a member of H(k) for each kind k.
Breaks
No such set exists. Let P = ∏k∈Kinds (k → Ty). It is a kind, so it is one of the indices, and its own factor at that index is P → Ty. Reading off that factor maps P onto P → Ty, since every other factor is nonempty. And P → Ty maps onto the power set of P, the set of all its subsets: send a function to the set of members that it sends to SN. So P would map onto its own power set, which Cantor’s theorem forbids.
Hence
Levels. The kinds of §32 are level 0, and they form a set. A kind of level n+1 may quantify over the kinds of level n. A type expression may quantify over the kinds of any one level, because that is an intersection of a nonempty collection of type sets.
Contrast
The same circle did no harm one level down, in narrow point 5. Every type set is a subset of one fixed set, the set of all terms. So the collection of all type sets is a set from the start, and an intersection cannot leave it. Kinds are built by function sets, each larger than the last, and no fixed set holds them all.
Status
This shows that the method breaks. By itself it does not show that U⁻ is inconsistent. System F is the warning: by a theorem of Reynolds it has no model in which → is the set of all functions, and it is consistent all the same, as this page shows with a model of another sort. For U⁻ the stronger fact is also true, for a different reason. Girard wrote down a closed term t with ⊢ t : ∀X.X in the larger System U, and Coquand and then Hurkens did the same in U⁻. That is quoted here and not proved. Erase the annotations from such a term and an untyped term is left that is not in SN. The paradox is that the rules of U⁻ accept it.

The definition of a type set in §5 is one of several. This section puts it beside Girard’s original definition and beside the plainest idea, which fails.

Saturated sets and reducibility candidates

The type sets of §5 are Tait’s saturated sets. Girard’s own proof used a different collection of sets in the same role.

Definition · Reducibility candidate

A term is neutral if it is not an abstraction.

A reducibility candidate is a set T of terms such that:

CR1
every member of T is in SN;
CR2
if t ∈ T and t → t′, then t′ ∈ T; Membership survives every step.
CR3
if t is neutral and every term that t steps to is in T, then t ∈ T. A variable is neutral and has no step, so every candidate contains every variable.

Lemma · Candidates are the type sets that are closed under stepshere, reviewed

Every reducibility candidate is a type set. Every type set satisfies CR1 and CR3. So a type set is a reducibility candidate if and only if it satisfies CR2, and CR2 is the only one of the three that a type set can fail.

Proof

A candidate is a type set. The SN condition is CR1. In the Base condition and the closure condition the term in question is neutral, so by CR3 it is enough that every term it steps to is a member.

For the Base condition, every step of x u1…un is inside an argument and gives a term of the same form. Argue by induction on the total length of the longest runs of the arguments.

For the closure condition, write s for (λx.t) u u1…un and s′ for t[u/x] u1…un, with s′ ∈ T and u ∈ SN. The head step takes s to s′. Any other step is inside t, u or some ui, and gives a term of the same form as s. The term after the head step of that term is reached from s′ by zero or more steps, so it is in T by CR2. Argue by induction on the longest runs of s′ and of u.

Every type set satisfies CR1 and CR3. CR1 is the SN condition. For CR3, let t be neutral with every term it steps to in T. Those terms are in SN, so t ∈ SN. A neutral term is either a variable applied to arguments, and then it is in T by the Base condition, or it has a head step. In that case the term after the head step is in T and the argument is in SN, so t ∈ T by the closure condition. ∎

Example · A type set that is not a candidate

Gen({I I}) from §5 contains I I and does not contain I, although I I → I. So it fails CR2. The reverse cannot happen in either collection: a set that contains I contains I I, by the closure condition. SN is both a type set and a candidate, by R1 (subterms).

Both collections are closed under ⇒ and under intersections, so either one proves the theorem, through the same four facts. For candidates the reason is short. If T and U are candidates, then T ⇒ U is a type set by the arrow lemma, and it satisfies CR2: if t ∈ T ⇒ U and t → t′, then for every u ∈ T the term t u is in U and steps to t′ u, so t′ u ∈ U by CR2 for U. CR2 passes to intersections, because it holds in each set. Neither is better throughout. Candidates keep a term while it runs. And CR3 names no form of term except “not an abstraction”, so if new forms of terms are added, as in limit 4 of §23, then it is enough to say which of them are neutral. Saturated sets are closed under unions by a proof of one line, which the existential types of §22 need. For candidates the union is a candidate too: by the lemma “Candidates are the type sets that are closed under steps”, two candidates are two type sets closed under steps, their union is a type set by the union lemma of §8, and it is closed under steps because each of the two is. The conditions of saturated sets are also direct statements about membership, which keeps each closure proof to a line.

That the union of two candidates is a candidate is a theorem of Riba’s, from 2007. He writes that the property “was hitherto unknown, and even often believed to be false”, and proves it for the Curry-style second-order λ-calculus, which is the setting of this page; there he also shows that the candidates are exactly the saturated sets that are closed under steps, which is the lemma “Candidates are the type sets that are closed under steps”. His theorem is more general: for a rewriting system in which candidates make sense, they are closed under union if and only if they are exactly the nonempty sets of strongly normalizing terms that are closed downward under a certain preorder on terms, which can fail elsewhere. The two-line proof of this paragraph is this page’s, and it uses that lemma in the place of his argument.

With the two collections a type expression names two sets, because ∀ is an intersection over a different collection in each. For ∀X.X both sets are Min, which belongs to both collections and is inside every member of each. For other type expressions this page does not know whether the two sets can differ; both contain every term that the rules give that type expression.

Plain sets

The plainest idea is to drop the conditions and let every set be a type set. There are two versions.

Any set of terms. Keep the terms and keep ⇒. Then ∅ is a type set, and ∅ ⇒ U is the set of all terms, as in narrow point 2. So membership says nothing about strong normalization. The rule “→ in” fails as well, because it rests on the closure condition. For example, let T = U = {y}. Then x[u/x] ∈ U for the only u ∈ T, but (λx.x) y is not the term y, so λx.x ∉ T ⇒ U.

Any set, with all functions. Leave the terms out. A type expression names a set of values of any sort, and A → B names the set of all functions from the one set to the other. For the simply typed λ-calculus this is the standard model. For System F no such model exists. This is Reynolds’s theorem of 1984, “polymorphism is not set-theoretic”, quoted here and not proved. Its proof is by counting. A model would contain a set P that is as large as the set of all functions from P → B to B, where B has two members, and Cantor’s theorem forbids that. Pitts later showed that the theorem depends on classical logic.

Sets of terms escape because their arrow is small. T ⇒ U contains terms only, and there are countably many terms, however many functions there are from T to U. Every type set is a subset of one countable set. So the collection of all type sets is a set, and an intersection over it is an ordinary operation.

§32 reads kinds in the plain way: ∗ is a set, and κ → κ′ is the set of all functions. If no kind quantifies over all kinds, then this causes no trouble. Narrow point 7 in §34 is what happens when one does, and it ends in the same appeal to Cantor’s theorem.

§36The three collections

Uses §7 The collection of type sets, §35 Other collections of sets. Used by §37.

§35 put Girard’s candidates beside the type sets of §5. There is a third collection between the two, and the three stand in a simple relation: they are one structure read three ways, as terms with their evaluation history, as sets of values, and as sets of values closed under running. The main line never needs this section. It says what the choice made in §5 means, and it makes exact the picture given there, that a type set is roughly a set of values.

Values, and the third collection

Definition · Value, evaluation, head-closed type set

A value is a strongly normalizing abstraction.

Let t be a strongly normalizing term. Its head steps are steps, so they end, at a term with no head step: an abstraction, or a term x u1…un. That term is the evaluation of t, written eval(t). It is a value, or it is in Base; in the second case t is said to get stuck.

A type set T is head-closed if the following holds: if s ∈ T and s →h s′, then s′ ∈ T.

Every head step of a strongly normalizing term is safe, because its argument is a subterm. So a head-closed type set is one that is closed under safe head steps in both directions. The lemma “Head-closed type sets are sets of values” shows that its members are exactly its values together with every term that evaluates to one of them, together with Min. The name “head-closed” is this page’s. From general knowledge, and not checked against sources: sets of this shape, every term that evaluates into a chosen set of values, are what the semantics of programming languages builds from a set of values, as in Harper’s note, and what proofs by tests produce for closed terms; the head-closed type sets are their form for open terms. We found no name for the collection in the literature, and that is the price of working with it.

The chain

Write SAT for the collection of all type sets, HC for the collection of head-closed type sets, and CR for the collection of reducibility candidates. The name HC is for this section; the letters SAT and CR are the usual ones for Tait’s and Girard’s collections.

Lemma · Head steps commute with other stepstextbook

Let t →h r be a safe head step, and let t → t′ be any step. Then t′ = r, or t′ →h r′ by a safe head step with r reaching r′ by zero or more steps.

So if t reaches r by k safe head steps and t reaches t′ by any steps, then t′ reaches, by at most k safe head steps, a term that r reaches by steps.

This is the textbook fact that head steps commute with the other steps, which is the heart of the standardization theorem in Barendregt’s book. The proof is given because the page needs the exact form with safe steps.

Proof

Let t = (λx.u) v v1…vn and r = u[v/x] v1…vn. The step t → t′ is the head step itself, and then t′ = r; or it is inside u, inside v, or inside some vi.

Inside u, with u → u′: t′ = (λx.u′) v v⃗ →h u′[v/x] v⃗, and u[v/x] v⃗ → u′[v/x] v⃗ by one step. Inside v, with v → v′: t′ →h u[v′/x] v⃗, and u[v/x] v⃗ reaches it by one step for each free occurrence of x in u. Inside vi: likewise. In each case the new head step is safe, because its argument is v or a reduct of v, and reducts of strongly normalizing terms are strongly normalizing, by R1 (subterms).

The second statement is proved by induction on k. If k = 0, then r = t, and t′ itself is the term wanted. Otherwise t →h t1 and t1 reaches r by k − 1 safe head steps. First, t′ is a reduct of t1, or t′ →h t1′ by a safe head step for some reduct t1′ of t1. This is shown by induction on the number of steps from t to t′: along the way, either the head step has been taken, after which every term is a reduct of t1, or the term at hand still has a safe head step to a reduct of t1, and the first statement carries that through the next step. Then the induction hypothesis, applied to the k − 1 head steps from t1 to r and to the reduct of t1 at hand, gives a term that r reaches by steps and that the reduct reaches by at most k − 1 safe head steps; with the one head step from t′, if there was one, that is at most k. ∎

CR ⊆ HC ⊆ SAT.

Each collection is closed under the intersection and under the union of a nonempty set of its members, computed as sets. So every nonempty set of members has a largest member below it and a smallest member above it, which is what “complete lattice” means in standard terms; and these are computed in the same way in all three.

Proof

Chain. A candidate is closed under all steps, by the lemma in §35, so under head steps.

Same operations. For SAT this is the intersection lemma and the union lemma of §8. Closure under head steps and closure under all steps are conditions on single members, so they pass to intersections and unions.

Same ends. SN is closed under every step, by R1 (subterms). For Min: let s ∈ Min, so s reaches a member b of Base by safe head steps, and let s → s′. By the lemma on commuting steps, s′ reaches by safe head steps a term b′ that b reaches by steps. A reduct of x u1…un is x u′1…u′n, which is in Base. So s′ ∈ Min. ∎

Going down and coming back

Definition · Four conversions between the collections

For a type set T:

hc(T) = cl(Th), where Th is T together with every term that a member of T reaches by head steps.

cr(T) = cl(T→), where T→ is T together with every term that a member of T reaches by steps.

kh(T) is the set of the members t of T such that every term that t reaches by head steps is in T.

k(T) is the set of the members t of T such that every term that t reaches by steps is in T.

cl is the closure of §5: add every term that reaches a member by safe head steps. The first two conversions enlarge a type set, the last two shrink it.

Lemma · Each conversion is the nearest memberhere, reviewed

smallest above
hc(T) is the smallest head-closed type set that contains T, and cr(T) is the smallest candidate that contains T.
largest below
kh(T) is the largest head-closed type set inside T, and k(T) is the largest candidate inside T.
nothing lost going up
If T is head-closed, then hc(T) = kh(T) = T; if T is a candidate, then cr(T) = k(T) = T.

So a conversion from a smaller collection to a larger one is the identity, and the two conversions back are a closure and a kernel: the nearest member of the smaller collection above, and the nearest below.

Proof

cr(T) is a candidate containing T. It contains T, so it contains Base, and it is inside SN by R1 (subterms) and R3 (safe head step). It is closed under safe head expansion, being a closure. For closure under steps: let t ∈ cl(T→), so t reaches some r ∈ T→ by safe head steps, and let t → t′. By the lemma on commuting steps, t′ reaches by safe head steps a term r′ that r reaches by steps, and r′ ∈ T→, because T→ is closed under steps. So t′ ∈ cl(T→).

cr(T) is the smallest. A candidate that contains T contains T→, by closure under steps, and then cl(T→), by the closure condition.

k(T) is a candidate inside T. Base ⊆ k(T), because a reduct of a member of Base is in Base ⊆ T. k(T) is closed under steps, because a reduct of a reduct is a reduct. For the closure condition: let s →h s′ be safe with s′ ∈ k(T), and let s″ be any term that s reaches by steps. By the lemma on commuting steps, s″ reaches, by at most one safe head step, a term that s′ reaches by steps; that term is in T, because s′ ∈ k(T); so s″ ∈ T, by the closure condition of T or because s″ is that term. Hence s ∈ k(T).

k(T) is the largest. A candidate inside T has all reducts of its members inside itself, so inside T.

Nothing lost going up is immediate from the definitions. The statements for hc and kh have the same proofs, with head steps in the place of steps; the commuting lemma is not even needed, because a head step from t stays on the head reduction of t. ∎

Example · What the conversions do to Gen({I I})

hc(Gen({I I})) = cr(Gen({I I})) = Gen({I}): going up adds I, and I I was already in Gen({I}). Coming back the other way, kh(Gen({I I})) = k(Gen({I I})) = Min: the only members of Gen({I I}) whose head reducts stay inside are the members of Min. The conversions lose the one thing Gen({I I}) records: that I I is in and its reduct is not.

The three readings

Lemma · Head-closed type sets are sets of valueshere, reviewed

Send a head-closed type set T to the set of values it contains, and send a set W of values to

TW = { t ∈ SN : eval(t) ∈ W, or t gets stuck }

bijection
The two maps are inverse to each other, between HC and the sets of values.
operations
Intersection and union of head-closed type sets are intersection and union of their sets of values. For a value v, Gen({v}) is head-closed and its set of values is {v}.
candidates
A head-closed type set is a candidate if and only if its set of values is closed under steps.
tell apart
Two strongly normalizing terms belong to the same head-closed type sets if and only if they have the same evaluation, or both get stuck. Compare the lemma in §7: all type sets together tell apart every two terms outside Min.
not so for SAT
A type set is not determined by its values: Gen({I I}) and Min contain no value at all, and differ.

So HC is, up to the bijection, the collection of all sets of values: a type set in HC is just a choice of which values belong. CR is the sets of values that are closed under steps. And SAT keeps, besides the values, the history: which terms on the way to a value are in and which are out.

Proof

TW is a head-closed type set with values W. It is inside SN by definition, and it contains Base, whose members are stuck. If s →h s′ is safe and s′ ∈ TW, then s ∈ SN by R3 (safe head step), and eval(s) = eval(s′), so s ∈ TW. If s ∈ TW and s →h s′, then eval(s′) = eval(s), so s′ ∈ TW. A value has no head step, so the values in TW are the values v with eval(v) = v ∈ W, which is W.

A head-closed T is TW for its set of values W. Let t ∈ T. Then eval(t) ∈ T, because T is closed under head steps. If eval(t) is a value, it is in W; otherwise t gets stuck. So T ⊆ TW. Conversely, let t ∈ TW. If eval(t) ∈ W ⊆ T, then t ∈ T by the closure condition, applied along the head steps from t to eval(t), which are safe. If t gets stuck, then t ∈ Min ⊆ T.

Operations. The values of an intersection or a union are the intersection or the union of the values. Gen({v}) = cl(Base ∪ {v}) is T{v}: a term is in it if and only if it reaches v or a member of Base by safe head steps.

Candidates. If T is a candidate, then a step inside a value of T gives a value of T, by closure under steps. Conversely, let W be closed under steps, let t ∈ TW and t → t′. If t gets stuck, then t ∈ Min, and t′ ∈ Min by the lemma on the chain. Otherwise t reaches eval(t) ∈ W by safe head steps, and by the lemma on commuting steps t′ reaches by safe head steps a term w′ that eval(t) reaches by steps. A reduct of an abstraction is an abstraction, so w′ is a value, and w′ ∈ W. So eval(t′) = w′ ∈ W, and t′ ∈ TW.

Tell apart. The head-closed type sets that contain a term t are the TW with eval(t) ∈ W, or all of them if t gets stuck. So two terms are in the same ones if and only if their evaluations are the same value, or both get stuck.

Not so for SAT. Min contains no abstraction, because every member reaches a member of Base by head steps and an abstraction has none. Gen({I I}) adds the terms that reach I I by safe head steps, none of which is an abstraction. ∎

Lemma · Only the head-closed type sets have complementshere, reviewed

In HC every type set T has a complement: T′ = (SN ∖ T) ∪ Min is head-closed, T ∩ T′ = Min and T ∪ T′ = SN. In SAT and in CR some type sets have no such complement: Gen({I I}) in SAT, and TI in CR.

So in HC a choice of values can be negated, and in the other two collections it cannot. In standard terms, HC is a power set up to Min, and so a complete Boolean algebra, and the other two are not. No result on this page uses this; it is listed because it is the sharpest way to say what the head-closed type sets are.

What a complement is not. The negation of System F is A → ∀X.X, which names ⟦A⟧ ⇒ Min: a type set in every collection, and not the complement of ⟦A⟧. The two differ as intuitionistic and classical negation differ, as the example “The arrow into Min is negation” in §8 shows: T ∩ (T ⇒ Min) has no closed member but is not empty, and T ∪ (T ⇒ Min) need not be SN. So the page never needs a complement, and working in the largest collection costs nothing here. Nor would a complement give a rule even in HC: a member of the complement of ⟦A⟧ is a term that evaluates to a value outside ⟦A⟧, and no term witnesses that of another, so no typing rule could conclude it; it is one more set that no type expression names, as most are by §11. Classical reasoning enters the semantics by another door, the tests of §37, where a continuation is the witness.

Proof

T′ is TW′ for the set W′ of values not in T: a strongly normalizing term is in T′ if and only if it gets stuck or evaluates to a value outside T. So T′ is head-closed, and the two equations hold by the items bijection and operations. In SAT, a type set T′ with Gen({I I}) ∪ T′ = SN contains I, which is not in Gen({I I}), and then I I by the closure condition; but I I is in Gen({I I}) and not in Min, so the intersection is not Min. In CR, a candidate T′ with TI ∪ T′ = SN contains λx.I x, which is not in TI, and then I by closure under steps; but I ∈ TI and I ∉ Min. ∎

Example · Three type sets, one from each collection

  • Gen({I I}) is a type set and not head-closed: it contains I I, and I I →h I, and I ∉ Gen({I I}).
  • Gen({λx.I x}) is head-closed, by the item operations: its only value is λx.I x. It is not a candidate: λx.I x → I by a step inside the abstraction, and I ∉ Gen({λx.I x}).
  • TI = Gen({I}) is a candidate, by the item candidates: its only value is I, which has no step.

preservation
If T and U are head-closed, then so is T ⇒ U; if they are candidates, then so is T ⇒ U. The intersection of a nonempty set of head-closed type sets, or of candidates, is one again.

Let ∀X.A name the intersection over all members of HC, or over all members of CR, instead of over all type sets, and let assignments take their values in that collection. Then Lemma N, the four facts, the soundness theorem and both corollaries hold.

Each step down the chain gives up some type sets, and with them some values of X, in return for an invariance of membership: under head steps, then under all steps. The set that a type expression names may change with the collection, because ∀ ranges over fewer sets; for ∀X.X it does not, and for other type expressions this page does not know, as §35 says. The theorem does not change.

Proof

Preservation. Let t ∈ T ⇒ U and t →h t′. For every u ∈ T, t u →h t′ u, because a head step survives one more argument, and t u ∈ U, so t′ u ∈ U by closure of U under head steps. So t′ ∈ T ⇒ U. For a step t → t′ that is not a head step, t u → t′ u is a step, and closure of U under steps gives the same conclusion. Intersections were treated in the lemma on the chain.

By the remark in §13 on what the proof asked of the collection that ∀ ranges over, it is enough that the collection consists of type sets, is closed under ⇒ and under nonempty intersections, and has a smallest member with no closed member. Remark · What the choice in §5 means

The definition in §5 picks the largest of the three collections, the one that asks least of a set. The other two are what remains when a further invariance is asked: that a term and its evaluation share their type sets, or that a term and all its reducts do. Limit 3 of §23, that a member can leave a type set by running, is the price of the largest collection; the head-closed type sets remove it for head steps and keep it for steps inside abstractions, as Gen({λx.I x}) shows, and the candidates remove it altogether.

The case for each is short. For SAT: it is the largest, every closure proof is one line, and it is the one with a name and a literature. For HC: it is exactly the sets of values, with complements, which is the object that the semantics of programming languages works with; its price is that it has no name in the literature. For CR: a term keeps its type sets while it runs, which is what typing usually promises, and it is Girard’s. The theorem does not care, by the lemma “Each collection carries the theorem”, and nothing in the main line depends on the choice; the main line asks only what the remark in §13 lists. §38 runs the same theory on pairs of terms, so that a type expression names a relation; for head-closed type sets that is a relation between values. §37 adds a fourth collection below the candidates, the sets defined by tests.

§37Type sets defined by tests

Uses §36 The three collections. Used by §44.

There is a way of giving System F a meaning in which a type expression names the terms that pass every test in some set of tests, and in which the conditions of a type set are never stated, because they follow. From general knowledge, not checked against sources for this page: it is the form used for classical logic and for languages with effects, where a test is a continuation, that is, a whole context waiting for the term. This section makes it exact for the simplest kind of test, an argument list, and places the sets it produces in the chain of §36. Classical logic itself is not on this page, but the collection of sets it works with is already visible here.

Definition · Tests, and the sets they define

A test is a finite list v1,…,vn of strongly normalizing terms, with n ≥ 0. A test is written v⃗ for short, and t v⃗ is t v1…vn.

A term t passes the test v⃗ if t v⃗ ∈ SN. The empty test is passed by every strongly normalizing term.

For a nonempty set P of tests, P⊥ is the set of terms that pass every test in P.

A set of terms is test-defined if it is P⊥ for some nonempty set P of tests.

Two clauses need a reason. The terms of a test are strongly normalizing because otherwise no term would pass it, by R1 (subterms), and P⊥ could be empty; the Base condition in the lemma on the fourth collection uses this clause. The set of no tests is excluded because every term passes all of its tests, and the set of all terms is not a type set. In the literature, from general knowledge, P⊥ is called the orthogonal of P, and a set of the form P⊥ a biorthogonal, because it is the orthogonal of its own orthogonal: write Q for the set of tests that every member of P⊥ passes; P ⊆ Q, so Q⊥ ⊆ P⊥; and every member of P⊥ passes every test in Q by the definition of Q, so P⊥ ⊆ Q⊥.

passes all

Proof

Passes all. The empty test: λx.y is a normal form, so it is in SN. A test v1,…,vn with n ≥ 1: (λx.y) v1 v2…vn →h y v2…vn is a head step, safe because v1 ∈ SN, and y v2…vn is in Base, so in SN by R2 (variable applied); so (λx.y) v⃗ ∈ SN by R3 (safe head step). And λx.y is not in Min, because every member of Min reaches a member of Base by head steps, by M2 (generated), while an abstraction has no head step and is not in Base.

Closed terms fail. If t ∉ SN, the empty test fails it. Let t ∈ SN. Some run from t ends in a normal form t̂, because every run is finite. t̂ is closed, because a step never adds a free variable. A closed normal form is an abstraction: by §2 it has one of three forms, a variable applied to arguments has a free variable, and an abstraction applied to arguments has a step. So t̂ = λx1.…λxk.s with k ≥ 1 and s not an abstraction; s is a normal form, as a subterm of one, so it is a variable applied to arguments, s = xi u1…um, and the variable is one of x1,…,xk because t̂ is closed. Take the test v1,…,vk,vk+1 with vj = I for j ≠ i and j ≤ k, with vi = λz1.…λzm.δ, which is δ itself if m = 0, and with vk+1 = δ. Each is a normal form, so in SN. Then t̂ v1…vk vk+1 reaches vi u1′…um′ δ by k head steps, where uj′ is uj with the vs put in for the xs; and that term reaches δ δ = Ω by m more head steps, because δ is closed and the substitutions for z1,…,zm change nothing in it. The terms uj′ need not be in SN; the run never looks inside them. So t̂ v⃗ reaches Ω, and it is not in SN, by R1 (subterms). The steps from t to t̂ are steps of t v⃗ as well, so t v⃗ reaches t̂ v⃗, and t v⃗ ∉ SN by R1 (subterms) again. ∎

Proof

Candidates. Let P be nonempty and T = P⊥. SN condition: pick a test v⃗ ∈ P; if t ∈ T then t v⃗ ∈ SN, so t ∈ SN by R1 (subterms). Remark · What tests are for

Nothing in the main line needs TT; it is a smaller collection than the candidates, it loses Min, and whether it keeps the union lemma was not checked. What it has that the other three collections lack is that a set is given by what is done to its members, and “what is done” can be richer than applying arguments. From general knowledge, not checked against sources for this page: for classical logic, as in Parigot’s λμ-calculus and in Krivine’s realizability, a test is a continuation, and passing a test is a property of the term in that context, fixed by a chosen set of acceptable outcomes; a set of tests then defines the set of terms that pass every one of them, and the arrow and the intersection are computed as in the lemma, with tests in the place of arguments. The closure condition is never stated in that setting, because it follows, as the item candidates shows for argument lists. That is the sense in which §44 says that tests grow from Tait’s side: what the lemma proves of P⊥ is the closure condition, undoing a safe head step, which is the condition §5 chose. A section on classical logic would start here and is not on this page.

§38Pairs: parametricity

Uses §13 The rules and the soundness theorem. No later section uses it.

On this page a type expression names a set of terms. Reynolds’s parametricity reads a type expression as a relation between terms, and draws from the rules alone conclusions about what a term of a given type expression can do. This section shows that the relational reading costs one definition and no new proof: the main line of the page, §5 to §13, is the same theory run on pairs of terms. The abstraction theorem falls out, and two of its consequences are worked out.

Definition · Pairs, and type sets of pairs

A pair is two terms (t, t′), in order. Everything is done to both sides at once.

The variable x, as a pair, is (x, x).

The application (t, t′) (u, u′) is (t u, t′ u′).

The abstraction λx.(t, t′) is (λx.t, λx.t′).

The substitution (t, t′)[(u, u′)/x] is (t[u/x], t′[u′/x]).

A pair is in SN if both of its terms are.

Base is the set of pairs (x u1…un, x v1…vn) with the same variable x and the same n on both sides, and all of u1,…,un, v1,…,vn in SN.

A pair takes a head step if both of its terms take one at once, and the step is safe if both arguments are in SN.

A relation is a set of pairs that satisfies the three conditions of §5, read for pairs: inside SN, containing Base, closed under undoing safe head steps. The arrow R ⇒ S, the intersection over all relations, cl and Gen are defined by the same words as for terms, with “pair” for “term”.

A relation relates two terms if the pair is a member. R ⇒ S relates two functions if they send related arguments to related results. A pair with a variable at the head on one side only, or with different variables at the head of its two sides, is in no Base; and if only one side has a head step, the pair takes none. Such pairs are simply never produced by the constructions.

Lemma · The main line runs on pairshere, reviewed

The definitions and proofs of §5, §8, §9, §10, §12 and §13 hold with pairs in the place of terms and relations in the place of type sets, word for word. In particular, with X ranging over all relations: every type expression names a relation; and if Γ ⊢ t : A, then for every assignment ρ of relations to variables and every choice of pairs (ui, ui′) ∈ ⟦Ai⟧ρ, the pair (t[u⃗/x⃗], t[u⃗′/x⃗]) is in ⟦A⟧ρ.

abstraction theorem
If ⊢ t : A, then (t, t) ∈ ⟦A⟧ρ for every assignment ρ of relations.

The abstraction theorem is Reynolds’s, and the route through saturated relations is standard; the claim of this lemma is only that the proofs on this page need no change.

Proof

The remark in §13 on what the proof asked of terms lists what the proofs of the sections named use about terms, and nothing else: R1 (subterms), R2 (variable applied) and R3 (safe head step) of Lemma R; that a head step survives one more argument, with the same argument; that (λx.t) u takes a head step to t[u/x] with argument u; that a variable is in Base, and a member of Base applied to a member of SN is in Base; that a member of Base has a free variable; and, for M2 (generated), that a member of cl(S) reaches S by safe head steps. Each holds for pairs, because each is checked on the two sides separately, and the two sides take their head steps together. The abstraction theorem is the soundness theorem read for pairs, in the case of an empty context, where there is nothing to replace. ∎

Example · Two free theorems

Let u, v, u′, v′ be closed strongly normalizing terms, and let no one of u, v reach the other by zero or more head steps, so in particular u and v differ, and likewise for u′, v′. The hypothesis is there so that “reaches u” and “reaches v” exclude each other.

  • Identity. If ⊢ t : ∀X.X→X, then t u reaches u by head steps. This needs no pairs: t ∈ ⋂C (C ⇒ C) by the soundness theorem of §13, so t u ∈ Gen({u}), so t u reaches u or a member of Base by head steps, by M2 (generated), and a closed term reaches no member of Base.
  • Choice. If ⊢ t : ∀X.X→X→X, then either t u v reaches u by head steps for all such u, v, or it reaches v for all of them. Without pairs one gets only that t u v reaches u or v, with the choice possibly depending on u and v. With pairs: (t, t) ∈ ⋂R (R ⇒ (R ⇒ R)). Take R = Gen({(u, u′), (v, v′)}). Then (t u v, t u′ v′) ∈ R, so by M2 (generated) for pairs the two terms reach, by head steps taken together, the pair (u, u′) or the pair (v, v′); a member of Base is excluded because both terms are closed. If t u v reaches u, then it does not reach v: a term has at most one head step, so if it reached both, one of u, v would reach the other. So the pair reached is (u, u′), and t u′ v′ reaches u′. So the choice is the same for every pair of inputs.

These are the simplest cases of what Reynolds and Wadler draw from parametricity. The second is the one that shows the gain: the relation R ties the behaviour of t on one pair of inputs to its behaviour on another, which no set of terms can do.

Remark · What changes, and what does not

Everything built on the main line by the same words runs on pairs too: the additions of §19 and §22, the families of §24, which become functions from pairs to relations, and the three collections of §36, where a head-closed relation is determined, by the same correspondence, by its pairs with no joint head step; among those are the pairs of values, and restricted to them it is a relation between values, which is the form in which parametricity is usually stated, but mixed pairs such as (I, y) are among them too. This was checked for this page by reading the proofs and is not written out.

What changes is what equality can mean. Under the relational reading, two functions are related at R ⇒ S exactly when they send related arguments to related results, so an equality read as a relation is extensional from the start, and function extensionality, quotient types and observational equality, which §39 had to turn away, have their home here. Working any of them out is not done on this page. Homotopy type theory and cubical type theory, where a proof of an equality carries structure of its own, are further away still, and this page names no home for them. The lemma “Type sets tell terms apart” of §7 still holds for relations, read for pairs; what the relational reading adds is not that the semantics identifies more terms, but that a type expression can now relate two different terms.

§39Equality type sets

Uses §7 The collection of type sets, §30 Equality and the Kleene trick, §33 System Fω: names and rules. No later section uses it.

The lemma “Type sets tell terms apart” in §7 says that two strongly normalizing terms belong to the same type sets only if they are the same term, or both are in Min. So the semantics identifies no two different terms: not convertible ones, such as I I and I, and not even a term and its head reduct. An equality between terms is therefore never built in. It has to be added as a type set, and this page has done that in two ways: EQ(u, v) in §25, built from ⋂ and ⇒, and E(u, v) in §30, which is SN or Min. This section says which relations between terms can be added in the second way, puts the two side by side, and says what an equality between type expressions is.

Equality as a type set

Definition · The equality type set of a relation

Let R be a relation between terms with two properties, called constant along steps and survives substitution: if u → u′, then u R v if and only if u′ R v, and the same on the right; and if u R v, then u[s/x] R v[s/x] for every term s and variable x.

For terms u and v, ER(u, v) is SN if u R v, and Min otherwise.

Convertibility has both properties, and it is the only relation on this page that does. Being the same term survives substitution and is not constant along steps: I I → I, and I is the same term as I while I I is not. Reaching the same term by head steps is not constant along steps either: λx.K x → K, and K reaches K, while λx.K x, an abstraction, has no head step and is not K.

Lemma · Every such relation can be addedhere, reviewed

Let R be as in the definition, and add the type expression {t ≃R t′} with the clause ⟦{t ≃R t′}⟧ρ = ER(t[ρ], t′[ρ]). Then:

type set
ER(u, v) is a type set, constant along steps of u and of v, so Lemma N holds with the new form by the addition lemma of §18 as extended in §26. This uses that R is constant along steps.
closed member
ER(u, v) has a closed member if and only if u R v.
true rules
The rule βR, which concludes Γ ⊢ I : {t ≃R t′} from nothing if t R t′, is true; this uses that R survives substitution. The rule ς is true if R is symmetric. The rule δ is true if K and K′ are not related by R.
false rules
The rules ρ and φ are false, for every R.

The rules are those of §30, with R in the place of convertibility. §30 is the case in which R is convertibility.

Proof

The proofs of §30 go through with R in the place of convertibility. Two places use the two properties of R: that R is constant along steps makes ER constant along steps, which the addition lemma needs, and that R survives substitution makes βR true, because t R t′ has to give t[ρ] R t′[ρ]. The counterexamples to ρ and φ in §30 use only that the variable y is an instance of e, and y ∈ Min ⊆ ER(K, I) whatever R relates; the failures come from I ∉ VI(K) and from K ∉ ID. ∎

When two type expressions name one set

The third kind of equality is between names. Two type expressions are equal as names if they name the same type set under every assignment. This is a statement about the semantics, not a judgment of the system: no rule concludes that two type expressions are equal as names, and no rule needs to. Three sufficient conditions are already on the page, in Lemma N: N2 (substitution), on which “∀ out” rests; N4 (term steps) in §26, on which term conversion rests; and N3 (type steps) in §33, on which conversion rests. None of them is necessary. ∀X.X and ∀X.∀Y.X name Min under every assignment, and neither is reached from the other by steps; the rules can carry a variable from each to the other, by “∀ out” and “∀ in”, but no rule states that the two are equal as names. Whether two type expressions name the same set is, in general, a question of the metatheory, and the page makes no claim about deciding it.

Remark · What this section does not cover

Function extensionality, quotient types and observational equality are statements about when two terms, or two functions, should count as equal. In a semantics where a type expression names a set of terms they have no home: the lemma of §7 says that the semantics tells terms apart, and the rules that would use such an equality meet limit 1 of §23. They belong to a semantics where a type expression names a relation between terms, which §38 sets up; working them out there is not done on this page.

Propositions, and using a proof. Proof assistants keep propositions apart from data. From general knowledge, not checked against sources for this page: in Coq a proof of a proposition may be used to build data only under a restriction on the proposition, and in the strict propositions of Gilbert, Cockx, Sozeau and Tabareau any two proofs of a proposition are convertible, with a restriction of the same kind. The two values of E show the shape of such a restriction in this semantics. From E(K, I) = Min, the false equation, the rule δ builds anything, and it is true. From E(I, I) = SN, the true equation, the rules ρ and φ build data, and they are false. What this semantics cannot express at all is that two proofs are the same proof: it tells every two terms apart. So in a semantics of sets, the only proof-irrelevant propositions are the two type sets SN and Min, true and false, in which a proof carries no information beyond its existence; every other type set has members that some type set tells apart. The semantics of §38, where a type expression names a relation, has a natural notion: a proposition is proof-irrelevant if its relation relates any two of its members. A function from such a relation into another must then send any two proofs to related results, which is the restriction on eliminating a proposition into data, stated as a fact about the model. This is not worked out on this page.

§40What a hypothesis means

Uses §30 Equality and the Kleene trick. No later section uses it.

A judgment Γ ⊢ t : A is a statement under hypotheses, the entries of Γ. On this page a hypothesis is read in one way throughout, and that reading decided several things that looked unrelated: why variables are in every type set, why consistency speaks of closed terms, why Cedille’s rules ρ and φ fail, and what a false hypothesis does. This section states the reading once and lists what follows from it.

Definition · The reading of a hypothesis

By the definition of a true judgment in §12 and §26, the hypothesis x : B means: x stands for an arbitrary member of the type set that B names. A judgment under Γ is true if it holds for every choice of members, one for each hypothesis.

Two consequences are immediate. A hypothesis never has no instance, because every type set contains the variable x itself, by the Base condition; so a judgment is never true for lack of instances. And a variable is a term that does nothing, as the remark on contexts in §13 says, so the instance “x itself” is always available, which is what C1 (strong normalization) uses.

Lemma · What a false hypothesis doeshere, reviewed

Let the type expression B name Min under every assignment, as ∀X.X does, or {K ≃ I} in §30. Then, for every Γ, t and A:

weakening
If Γ ⊨ t : A, then Γ, e : B ⊨ t : A, for a variable e not free in t, Γ or A. This holds for every B, and does not use that B names Min.
from it
Γ, e : B ⊨ e : A, for every A: a proof of a false statement proves everything.
not all
e : B ⊨ Ω : A is false, and so is e : B ⊨ t : A for every closed term t and every A that names Min, such as e : ∀X.X ⊨ I : ∀X.X.

So a false hypothesis gives “anything from it” but not “anything at all”: a judgment under a false hypothesis still says something about its term. The instances of e are the members of Min, terms that get stuck at a variable, and the term t has to be in ⟦A⟧ when e is any of them.

Proof

Weakening. Adding a hypothesis that t, Γ and A do not mention changes neither t[ρ] nor the sets, by N0 (free variables).

From it. Every instance of e is in Min, and Min is inside ⟦A⟧ρ by M3 (smallest).

Not all. Ω[ρ] = Ω ∉ SN, so it is in no type set. A closed t has t[ρ] = t, and Min has no closed member, by M3 (smallest). ∎

Here is what the reading decided, in the order the page met it.

  • The Base condition of §5 is the reading applied to C1 (strong normalization): the judgment x : A ⊢ x : A has to hold of the instance “x itself”, so x has to be in every set that A can name; and then so has x u, because the arrow checks its members on x. Narrow point 2 in §6 showed that nothing less works.
  • Consistency in §13 is stated for closed terms because an open term under a hypothesis is never excluded: e : ∀X.X ⊢ e : ∀X.X is derivable and true. What cannot be derived is a closed proof of ∀X.X.
  • Limit 1 of §23: a rule that draws a conclusion from the mere existence of a member of some type set is false, unless the conclusion holds of every member of that type set, because every type set has members, the variables. The rules ρ and φ of §30 are two such rules: each concludes something about a term from a hypothesis e : {t ≃ t′}, and the hypothesis has instances even when the equation is false. The rule δ is true because it draws its conclusion from Min itself.
  • Stump’s semantics for Cedille, in the remark of §30, takes the other reading: a type names a set of closed terms, so a false hypothesis has no instance, every judgment under it is true for lack of instances, and ρ and φ hold. The price of that reading is that the theorem is consistency alone, not strong normalization, and the remark lists what else it changes.
  • Casts in §31: an inclusion between type sets cannot be a hypothesis, for the same reason, and became a condition on an index set instead.

Remark · What the reading does not give

Under this reading a hypothesis is a term, never a fact about terms. “x is a natural number” can be a hypothesis, by giving x a type expression for the naturals; “u and v are equal” can be one only as a type set, EQ(u, v) or E(u, v), whose members are proofs, and the lemma on ER in §39 says which equalities can be added that way. A hypothesis whose content is used by retyping a term, as ρ, φ and casts do, is what the reading cannot give.

§41Impredicativity, paid once

Uses §17 How strong the proof has to be, §23 Limits of adding rules, §31 Inductive types three ways, §33 System Fω: names and rules. No later section uses it.

Narrow point 5 in §11 said that the intersection over all type sets is impredicative: it defines a type set by quantifying over a collection that contains that type set. §17 said what that costs, more than second-order arithmetic. The same move is made in several more places on the page, each time with a different index set. This section lists them and shows that the price is paid once, with the kinds of Fω as the one exception.

Lemma · Every intersection on this page is over a sethere, reviewed

Every intersection that this page forms is indexed by one of the following sets, or by a subset of one of them: a type set, which is a set of terms; the collection of all type sets; the collection of all families; a kind of §32. Each of these is a set in ordinary set theory. The type sets and the families are both subsets of one power set of a set of terms or of pairs of terms; a kind is built from the type sets by one more power set for each arrow in it.

So the circle of narrow point 5 is always the same circle: a set is defined by an intersection over a collection, and the collection was fixed, as a set, before the definition. The one collection that is not a set is that of all kinds, and narrow point 7 in §34 is what happens when an intersection is taken over it.

Proof

The intersections on the page are: over all type sets, in §8; over a nonempty set of type sets, for ∧ in §19 and for the fixed point of §22, which intersects the type sets C with F(C) ⊆ C; over all families, in §24; over the members of a type set, in §27 and §29, which is a subset of the set of all terms; over the type sets inside a given one, over all type sets and over all families again, in §31; and over a kind, in §32. A type set is a subset of the set of terms, so the type sets form a subset of its power set. A family V is determined by the set of pairs (u, t) with t ∈ V(u), which is a subset of the set of pairs of terms; so the families form, up to this coding, a subset of the power set of the pairs of terms, one level up from the terms, exactly as the type sets are. A kind is built from the set of type sets by function sets, and a function set is a subset of the power set of a product, one level up each time. ∎

§42Erasure: terms with annotations

Uses §13 The rules and the soundness theorem, §26 Dependent types: names and rules, §29 Implicit products, §30 Equality and the Kleene trick, §33 System Fω: names and rules. Used by §43.

Every term on this page is untyped, and every rule leaves the term as it is or builds it from the terms of the premises. The usual presentations write type expressions inside terms: λx:A.t, ΛX.t, t [B], and more for the larger systems. The remark on Church style in §13 said how the theorem reaches such terms for System F. This section states the argument once, as a lemma with one hypothesis, and lists what each annotated form on this page erases to. It is the one place where the page meets the terms that proof assistants check.

Definition · Erasure, loud and silent steps

An annotated calculus is a set of annotated terms, together with steps of its own between them and with an erasure.

The erasure of an annotated term t, written |t|, is a term of §1.

A step of the annotated calculus from t to t′ is loud if |t| → |t′| is a step, and silent if |t| = |t′|.

The calculus is erasable if every one of its steps is loud or silent, and no annotated term has an infinite run of silent steps.

Erasure lemma · No infinite run passes from erasures to annotated termshere, reviewed

Let the annotated calculus be erasable, and let t be an annotated term with |t| ∈ SN. Then t has no infinite run.

So if, for every derivable judgment about an annotated term t, the erased judgment about |t| is derivable in a system whose rules this page has shown true, then no typable annotated term has an infinite run.

Proof

Suppose t has an infinite run. If only finitely many of its steps are loud, then from some point on every step is silent, and that is an infinite run of silent steps, which the calculus does not have. So infinitely many steps are loud, and each loud step is a step of the erasure, while a silent step leaves the erasure unchanged. Erasing the whole run gives an infinite run of |t|, against |t| ∈ SN.

For the second statement, C1 (strong normalization) of the erased system gives |t| ∈ SN, and the first statement gives the claim. ∎

Two things have to be checked for each annotated calculus, and they are the whole content of the lemma: that every step is loud or silent, and that silent runs end. §43The λ-cube

Uses §26 Dependent types: names and rules, §34 New kinds, and the kind of all kinds, §42 Erasure: terms with annotations. No later section uses it.

System F is one corner of a cube of eight systems, described by Barendregt. The starting corner is the simply typed λ-calculus, whose type expressions are built from arrows alone. Three features can be added to it independently. Each lets one sort of thing depend on another.

FeatureWhat may depend on whatWhat the semantics addsOn this page
Polymorphisma term on a type expression: ∀X.A⋂ over all type sets§8 to §13

The definition of a type set in §5 serves all eight corners. What changes from corner to corner is which type sets get names.

  • Without polymorphism there is no ⋂ and no impredicative definition. The set for each type expression can be defined by recursion on the type expression, narrow point 5 does not arise, narrow point 6 shrinks to one lemma proved by recursion on the type expression, and what is left is Tait’s proof of 1967.
  • Type operators cost what §32 and §33 show. Kinds are plain sets, with no conditions to check.
  • Dependent types. Πx:A.B names a dependent arrow, which is a type set by the proof of the arrow lemma. There is one new obligation. A type expression can now contain a term, and if that term takes a step, then the type expression must still name the same set, because the rule of term conversion says so. That is why a family is asked to be constant along steps. §26 carries this out.

So in this semantics the three features cost about the same, and they do not interfere. Each adds names, and none changes the collection of type sets. This is a statement about the setting of this page, where terms carry no annotations. The usual presentations of the dependent corners annotate terms with type expressions, which in turn contain terms. Showing that every term is strongly normalizing, annotations included, takes more bookkeeping than §26 does: the erasure lemma of §42 says exactly what is missing. One known route, due to Geuvers and Nederhof, maps the Calculus of Constructions into Fω. That is quoted and not checked here.

Where type operators and dependent types meet. The families of §24 form one more kind. Write term → ∗ for it, and term → κ for the functions from terms to the members of κ that are constant along steps. A family variable is then a variable of the kind term → ∗. The type expression λx.B names the family w ↦ ⟦B⟧ρ[x↦w], and A[P:=x.B] is the ordinary substitution of λx.B for P, followed by steps inside the type expression. With polymorphism, functions on type sets and dependent types together, this is the last corner of the λ-cube, the Calculus of Constructions, in the form without annotations that this page uses. This paragraph is a sketch: the clauses and rules for the kinds term → κ are not written out.

How strong a proof has to be. §17 treats System F. The same pattern shows across the systems. The rows are quoted from the literature.

Past the cube. The Calculus of Inductive Constructions, the theory behind proof assistants such as Coq and Lean, adds two things to the last corner. Universes are a tower of levels, like the levels of kinds in §34, and each level needs a set that is closed under everything below it. Inductive types add new forms of terms, so limit 4 (new forms of terms) in §23 applies and §5 has to be redone. Both are much harder than anything here, and this page does not attempt them.

§45Harper’s note

Uses §15 Looking back. No later section uses it.

Robert Harper’s note How to (Re)Invent Tait’s Method proves a smaller theorem by the same method. It is also written the same way: try the obvious induction, watch it fail, strengthen. Reading the two side by side shows which of the demands of §15 make the definition here more delicate than his.

The same skeleton. Both proofs strengthen the claim three times. From a property of whole terms to a property at every type expression (his hereditary termination, narrow point 1 here). Then closure under undoing a head step (his head expansion lemma, the closure condition here). Then a statement about open terms under substitution (his final theorem about open terms, the definition of a true judgment here).

Why his proof needs less. His note makes none of the three demands of §15.

  • Steps in any order. Under head steps alone, (λx.y) Ω runs to y and stops. A discarded argument is never run. So undoing a head step never brings in a term whose evaluation runs forever, and narrow point 3 does not arise.
  • Open terms and steps under λ. His theorem is about closed programs that return an answer, and he remarks that the form “sends hereditarily terminating terms to hereditarily terminating terms” suits exactly that case. Getting a term’s own strong normalization out of that form is what the variable x as argument is for. Narrow point 2 is the price.
  • ∀. His predicate is indexed by type expressions and defined by recursion on them, which is the definition that fails in narrow point 5. Replacing “one predicate per type expression” by “any set that satisfies three conditions” turns his one-word lemma into a condition that must be chosen and must survive ⇒. That is narrow points 4 and 6.

His exercises point the same way as §22 and §23. Sums need the form “evaluates to a value of this form”, and he asks what goes wrong with the other form. Numbers are defined as the strongest property closed under zero and successor, which is the least fixed point of §22.
