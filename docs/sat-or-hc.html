A side-by-side reading of The Narrow Path

SAT or HC

The page defines a type set with Tait’s three conditions (SAT): inside SN, containing Base, closed under undoing safe head steps. This comparison shows what the page would say if the definition asked, in addition, that a type set is closed under taking head steps (HC, the head-closed type sets of §36). For every definition, lemma, example and remark that would change, the version on the page comes first, and the version under HC below it; in a changed item the words that go are struck through and the words that come are marked. An item that would disappear is followed by an empty frame; an item that would have to be added is preceded by one. Items whose statement does not change are listed once, with what happens to their proofs. Nothing here is on the main page.

In one paragraph

The theorem and its proof do not change: no fact and no rule uses the added direction, which is why the SAT page can call its definition the narrow path and the HC page could not (narrow point 5 below is a trial that succeeds). What changes is the picture and the examples. Under HC a type set is exactly a set of values, the lemma that says so moves next to the definition, and the semantics identifies a term with its evaluation; Gen({I I}) gains I, the chain of Lemma L collapses, limit 3 shrinks to steps inside abstractions, and Gen({λx.I x}) takes over the role of the escaping member. Every addition pays one more line, that its set is closed under head steps. §36 changes sides: the page’s collection becomes the middle one, the complements lemma is about it, and the remark has to explain why the largest collection was not taken.

§36 The three collections Definition · Value, evaluation, head-closed type set deleted under HC

SAT — as on the page

Definition · Value, evaluation, head-closed type set

A value is a strongly normalizing abstraction.

Let t be a strongly normalizing term. Its head steps are steps, so they end, at a term with no head step: an abstraction, or a term x u1…un. That term is the evaluation of t, written eval(t). It is a value, or it is in Base; in the second case t is said to get stuck.

A type set T is head-closed if the following holds: if s ∈ T and s →h s′, then s′ ∈ T.

Every head step of a strongly normalizing term is safe, because its argument is a subterm. So a head-closed type set is one that is closed under safe head steps in both directions. The lemma “Head-closed type sets are sets of values” shows that its members are exactly its values together with every term that evaluates to one of them, together with Min. The name “head-closed” is this page’s. From general knowledge, and not checked against sources: sets of this shape, every term that evaluates into a chosen set of values, are what the semantics of programming languages builds from a set of values, as in Harper’s note, and what proofs by tests produce for closed terms; the head-closed type sets are their form for open terms. We found no name for the collection in the literature, and that is the price of working with it.

A pair is two terms (t, t′), in order. Everything is done to both sides at once.

The variable x, as a pair, is (x, x).

The application (t, t′) (u, u′) is (t u, t′ u′).
