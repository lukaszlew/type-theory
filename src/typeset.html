In everyday use the word “type” covers two things. This page keeps them apart and never uses the word alone. A type expression is something one writes, such as X → X. Type expressions arrive only in {{names}}. A type set is a set of terms that satisfies the three conditions of the definition. The bare word is left only inside a few standard names, such as “dependent types”.

Definition · Type set

Write Base for the set of all terms x u1…un with n ≥ 0 and u1,…,un ∈ SN: a variable applied to any number of strongly normalizing arguments. For example y, y I and y δ δ are in Base. By R2 (variable applied) every member of Base is in SN. Base is what every type set starts from.

For a set S of terms, write cl(S), the closure of S, for S together with every term that reaches a member of S by safe head steps. For example cl({K}) contains K, (λb.K) y and K K y.

A type set is a set T of terms that satisfies three conditions. They are called the SN condition, the Base condition and the closure condition.

SN
T ⊆ SN. Every member of T is strongly normalizing. This is W1 (inside SN), the purpose.
Base
Base ⊆ T. Needed for W5 (variables) and for W2 (arrow). Every type set contains the same set Base. So for every variable x and all strongly normalizing terms u and v, the terms x, x u and x u v are in every type set, and so on for any number of arguments.
closure
cl(T) ⊆ T. Equivalently: if s →h s′ is safe and s′ ∈ T, then s ∈ T. Needed for W3 (abstraction). Written out: if t[u/x] u1…un ∈ T and u ∈ SN, then (λx.t) u u1…un ∈ T, for every n ≥ 0. Membership survives undoing a head step that discards nothing dangerous. Only the argument u has to be asked about. The step may have thrown u away, so nothing is known about it. The other arguments u1,…,un are subterms of a member of T, so they are in SN already, by the SN condition and R1 (subterms). SN has this property by R3 (safe head step).

In short, a type set is a set between Base and SN that is closed under undoing safe head steps. The definition talks about terms and steps only. It does not mention type expressions. Those come only in {{names}}, as names for some of the type sets.

A picture to carry through the page. A type set is, roughly, a set of values, that is, of strongly normalizing abstractions, together with every term that reaches one of them by safe head steps, together with the terms that get stuck at a variable, which belong to every type set. “Roughly” because a type set may contain a term and not the term that its head step leads to; {{families}} makes the picture exact and says what the word hides.

Definition · Gen(S) and Min

For a set S of strongly normalizing terms, Gen(S) = cl(Base ∪ S). It is called the set generated by S.

Min = Gen(∅) = cl(Base).

Lemma M · Three facts about type setshere, reviewed

M1
Largest. SN is a type set, and every type set is inside it.
M2
Generated. For a set S of strongly normalizing terms, Gen(S) is a type set, the smallest one that contains S. A term t is in it if and only if t ∈ SN and its head steps lead to a member of S or of Base. Zero head steps are allowed.
M3
Smallest. Min is inside every type set. Every member of Min has a free variable, so Min has no closed member.
Proof

M1. The SN condition holds trivially, the Base condition is R2 (variable applied), and the closure condition is R3 (safe head step). A type set is inside SN by the SN condition.

M2. The members of S are in SN by assumption and the members of Base by R2 (variable applied), and undoing a safe head step keeps a term in SN, by R3 (safe head step). So the SN condition holds, and the Base condition and the closure condition hold by construction. Any type set that contains S contains Base by the Base condition and satisfies the closure condition, so it contains Gen(S).

For the membership condition: a member reaches Base ∪ S by safe head steps, and it is in SN by the SN condition. In the other direction, if t ∈ SN then every argument met along its head steps is in SN, so those head steps are safe.

M3. Every type set contains Gen(∅), by M2 (generated). A member of Base has a free variable, the variable that is applied, and undoing a head step never removes a free variable. ∎

Sets that satisfy these three conditions are known as saturated sets, after Tait. Girard’s reducibility candidates are defined by a different and stronger list of conditions, and {{cmpsets}} compares the two.

Type sets differ from type expressions more than the shared word suggests. There are far more of them, so most type sets have no type expression that names them; {{allsets}} counts. One term is in many type sets at once. And membership is a fact about how the term runs, whether or not any rule can derive it. The proof never uses a particular type set built by hand, such as the G of the next examples. Such type sets matter because ∀ will range over all type sets, and not over type expressions. So it ranges over the hand-built ones too.

Example · The largest and the smallest type set

SN is the largest, by M1 (largest). It contains I, K, δ and I I, and it does not contain Ω.

Min is the smallest, by M3 (smallest). It contains Base, for instance y and y δ δ, and also (λz.y) I, whose head step leads to y. It does not contain I, or any other closed term.

Example · A type set built from two terms

Let G = Gen({K, I I}). Members:

  • K and I I, the two chosen terms.
  • y, y δ δ and y (I I): members of Base.
  • I (I I) and (λz.K) y: one head step leads to a chosen term.
  • K K y: two head steps lead to K, through (λb.K) y.
  • (λz.z K) y: one head step leads to y K, which is in Base.

Not members:

  • I. It is in SN and has no head step, and it is neither chosen nor in Base.
  • K K. Its head step gives λb.K, an abstraction that is not K.
  • λx.K x. It has no head step, although one step inside it gives K.
  • Ω and K I Ω. They are not in SN.

Example · A member can leave by running

I I is in G, and I I → I, but I is not in G. A type set need not keep a term while it runs. The same is true of Gen({I I}), which contains I I and not I; {{limits}} and {{cmpsets}} use that type set. The other direction cannot happen: if I is in a type set, then I I is in it too, by the closure condition. Nothing later needs a type set to keep a term while it runs.

Example · Sets that are not type sets

  • ∅ fails the Base condition.
  • {I} fails the Base condition and the closure condition.
  • Base itself fails only the closure condition, which asks for (λz.y) I. Its closure cl(Base) is Min.
  • The set of all terms, and SN with Ω added, fail the SN condition.
  • Min with I added and nothing more fails only the closure condition, which asks for I I as well.

Definition · Two hand-built type sets

TI = Gen({I}).

TK = Gen({K}).

Later examples use these two to check which terms belong to other sets. TI contains I, I I and (λz.I) y, and does not contain K, δ or λx.I x. TK is the same with K in the place of I.
