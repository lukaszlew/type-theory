The lemma “Type sets tell terms apart” in {{structure}} says that two strongly normalizing terms belong to the same type sets only if they are the same term, or both are in Min. So the semantics identifies no two different terms: not convertible ones, such as I I and I, and not even a term and its head reduct. An equality between terms is therefore never built in. It has to be added as a type set, and this page has done that in two ways: EQ(u, v) in {{darrow}}, built from ⋂ and ⇒, and E(u, v) in {{equality}}, which is SN or Min. This section says which relations between terms can be added in the second way, puts the two side by side, and says what an equality between type expressions is.

Equality as a type set

Definition · The equality type set of a relation

Let R be a relation between terms with two properties, called constant along steps and survives substitution: if u → u′, then u R v if and only if u′ R v, and the same on the right; and if u R v, then u[s/x] R v[s/x] for every term s and variable x.

For terms u and v, ER(u, v) is SN if u R v, and Min otherwise.

Convertibility has both properties, and it is the only relation on this page that does. Being the same term survives substitution and is not constant along steps: I I → I, and I is the same term as I while I I is not. Reaching the same term by head steps is not constant along steps either: λx.K x → K, and K reaches K, while λx.K x, an abstraction, has no head step and is not K.

Lemma · Every such relation can be addedhere, reviewed

Let R be as in the definition, and add the type expression {t ≃R t′} with the clause ⟦{t ≃R t′}⟧ρ = ER(t[ρ], t′[ρ]). Then:

type set
ER(u, v) is a type set, constant along steps of u and of v, so Lemma N holds with the new form by the addition lemma of {{price}} as extended in {{dep}}. This uses that R is constant along steps.
closed member
ER(u, v) has a closed member if and only if u R v.
true rules
The rule βR, which concludes Γ ⊢ I : {t ≃R t′} from nothing if t R t′, is true; this uses that R survives substitution. The rule ς is true if R is symmetric. The rule δ is true if K and K′ are not related by R.
false rules
The rules ρ and φ are false, for every R.

The rules are those of {{equality}}, with R in the place of convertibility. {{equality}} is the case in which R is convertibility.

Proof

The proofs of {{equality}} go through with R in the place of convertibility. Two places use the two properties of R: that R is constant along steps makes ER constant along steps, which the addition lemma needs, and that R survives substitution makes βR true, because t R t′ has to give t[ρ] R t′[ρ]. The counterexamples to ρ and φ in {{equality}} use only that the variable y is an instance of e, and y ∈ Min ⊆ ER(K, I) whatever R relates; the failures come from I ∉ VI(K) and from K ∉ ID. ∎

When two type expressions name one set

The third kind of equality is between names. Two type expressions are equal as names if they name the same type set under every assignment. This is a statement about the semantics, not a judgment of the system: no rule concludes that two type expressions are equal as names, and no rule needs to. Three sufficient conditions are already on the page, in Lemma N: N2 (substitution), on which “∀ out” rests; N4 (term steps) in {{dep}}, on which term conversion rests; and N3 (type steps) in {{fomega}}, on which conversion rests. None of them is necessary. ∀X.X and ∀X.∀Y.X name Min under every assignment, and neither is reached from the other by steps; the rules can carry a variable from each to the other, by “∀ out” and “∀ in”, but no rule states that the two are equal as names. Whether two type expressions name the same set is, in general, a question of the metatheory, and the page makes no claim about deciding it.

In Fω the statement can also be made a type expression, in the way {{darrow}} made an equation between terms one.

Definition · Equality of two type expressions, as a type expression

For type expressions A and B of the kind ∗, A ≐ B is short for the type expression ∀F:∗→∗. F A → F B of Fω.

Under ρ it names ⋂H (H(⟦A⟧ρ) ⇒ H(⟦B⟧ρ)), an intersection over the kind ∗ → ∗, so H ranges over all functions from type sets to type sets. A cast is the rule that uses a proof of such an equation without applying it: from Γ ⊢ e : A ≐ B and Γ ⊢ t : A conclude Γ ⊢ t : B. The proof e does not appear in the conclusion.

Write ⊥ for ∀X:∗.X. With the cast added to the rules of Fω, the judgment with the context h : ∀X:∗.∀Y:∗. X ≐ Y, the term δ δ and the type expression ⊥ is derivable, and δ δ = Ω is not in SN. So no semantics that proves C1 (strong normalization) can make the cast true.

The derivation is the counterexample of Abel and Coquand, with the annotations erased. Quoted from their paper. Their cast is a constant with a step of its own, which removes it if the two type expressions are convertible and does not look at the proof; with it, normalization fails for a type theory with an impredicative universe of propositions and an equality whose proofs are not inspected, already under the hypothesis that all propositions are equal. They adapt Girard’s counterexample to normalization for System F with a test for equality of type expressions. They note: “Consistency and canonicity is not at stake”; and they compare the situation to type theories in which a proved equation may be used as a conversion. A second term of theirs has no hypothesis and needs only an axiom that any two true propositions are equal.

Measured against this page, the cast is the rule φ of {{equality}} one level up: there an equation between terms retypes a term, here an equation between type expressions does, and in both the proof is used without being applied. Limit 1 of {{limits}} is the reason in both: the hypothesis has the variable h as an instance whatever the equation says. Their remark on consistency matches what {{equality}} reports of Stump’s semantics, which gives up strong normalization, makes such rules true and proves consistency.

Proof

Closed member. If the two sets are one set T, then I ∈ H(T) ⇒ H(T) for every H, because I ∈ C ⇒ C for every type set C, by {{ops}}. If they differ, let H be the function that gives SN at ⟦A⟧ρ and Min at every other type set; it is a member of ∗ → ∗, as every function is. A member e is then in SN ⇒ Min, and if it were closed, e I would be a closed member of Min, against M3 (smallest).

Applying. Instantiate at the function H(C) = C, and apply.

Cast. Let Γ be h : X ≐ Y, t : X. The two judgments above the rule are derivable by the variable rule, so they are true. The judgment below it is Γ ⊢ t : Y. Take ρ(X) = SN and ρ(Y) = Min, replace h by a variable, which is a member of every type set, and replace t by I. Then I ∈ SN and I ∉ Min.

Remark · What this section does not cover

Function extensionality, quotient types and observational equality are statements about when two terms, or two functions, should count as equal. In a semantics where a type expression names a set of terms they have no home: the lemma of {{structure}} says that the semantics tells terms apart, and the rules that would use such an equality meet limit 1 of {{limits}}. They belong to a semantics where a type expression names a relation between terms, which {{pairs}} sets up; working them out there is not done on this page.

Propositions, and using a proof. Proof assistants keep propositions apart from data. From general knowledge, not checked against sources for this page: in Coq a proof of a proposition may be used to build data only under a restriction on the proposition. Quoted from Abel and Coquand: in the strict propositions of Gilbert, Cockx, Sozeau and Tabareau an equality can be defined, but its proofs cannot be used to build anything that is not a strict proposition itself; under that restriction normalization is proved for the predicative case, and for an impredicative universe it is open. The two values of E show the shape of such a restriction in this semantics. From E(K, I) = Min, the false equation, the rule δ builds anything, and it is true. From E(I, I) = SN, the true equation, the rules ρ and φ build data, and they are false. What this semantics cannot express at all is that two proofs are the same proof: it tells every two terms apart. So in a semantics of sets, the only proof-irrelevant propositions are the two type sets SN and Min, true and false, in which a proof carries no information beyond its existence; every other type set has members that some type set tells apart. The semantics of {{pairs}}, where a type expression names a relation, has a natural notion: a proposition is proof-irrelevant if its relation relates any two of its members. A function from such a relation into another must then send any two proofs to related results, which is the restriction on eliminating a proposition into data, stated as a fact about the model. This is not worked out on this page.
