Some type sets vary with a term. Such a varying type set is called a family. The dependent arrow, self types and the dependent intersection are built from families.

Definition · Family

A function from terms to type sets is a function V that gives a type set V(u) for every term u.

Two terms are convertible if they are joined by steps, taken in either direction.

A family is a function from terms to type sets that is constant along steps: if u → u′ then V(u) = V(u′). So a family gives convertible terms the same type set.

For a function F that gives a type set for each family, ⋂V F(V) is the intersection indexed by the set of all families, in the sense of {{ops}}: the terms that are in F(V) for every family V.

The set of all families is not empty, because the constant functions are families. So ⋂V F(V) is a type set by the intersection lemma of {{ops}}, and generalize and instantiate of {{facts}} hold for it. Like the intersection over all type sets, this intersection is impredicative.

Remark · Two modeling choices, and what each costs

A family is defined on all terms, and not only on the members of some type set. The reason is that the self type of {{self}} and the dependent intersection of {{dinter}} apply V to the very term that is being tested, which may be any strongly normalizing term. So V has to be defined on all of SN at least, and defining it on all terms costs nothing more. The price is that no rule says which type expressions are well formed: in P t of {{dep}}, the term t may be any term. The usual presentations give P a domain, and {{self}} reports what that changes in System S.

A family is constant along steps. Each construction built from a function from terms to type sets asks something of that function, and the list is this. The dependent arrow of {{darrow}} and the intersection over the members of a type set in {{implicit}} ask nothing. The self type of {{self}} and the dependent intersection of {{dinter}} ask that the function is constant along safe head steps. The rule of term conversion in {{dep}} asks that it is constant along all steps, so that a term inside a type expression can be run without changing what the type expression names; and so does the rule “∀ out, for families” there, because the function w ↦ ⟦B⟧ρ[x↦w] that it instantiates at is constant along steps of w only if every family is constant along all steps, as the proof of N4 (term steps) shows. The page asks the strongest of the three of every family, so that one notion serves every construction. The price is that ∀P ranges over fewer functions than it otherwise could, and the example “A function that is not a family” shows one that is excluded; EQ(u, v) of {{darrow}} is weaker by the same amount. Each lemma that follows states which of the three it needs.

Definition · The family Vv

For a term v, Vv is the function that gives SN at every term convertible with v, and Min at every other term.

A step does not change which terms a term is convertible with, so Vv is a family. It tells the terms convertible with v apart from all others, and {{darrow}} and {{equality}} check other families against it.

Example · VI

VI(I I) = SN, because I I → I. VI(K) = Min, because K and I are not convertible. That rests on the Church–Rosser theorem, quoted here and not proved: two different normal forms are never convertible.

Example · A function that is not a family

Let V(u) be SN if u is the term I itself, and Min otherwise. Every value is a type set. But I I → I, and V(I I) = Min while V(I) = SN. So V is not constant along steps, and it is not a family. {{dep}} shows which rule would be false if it were one.

Example · A family that no program can decide

Let W(u) be SN if u has a normal form, and Min otherwise. It is a family: if u → u′ and u has a normal form n, then u′ reaches n too, by the Church–Rosser theorem; and if u′ has a normal form, then so does u, through u′. No program decides whether a term has a normal form, which is a standard fact, quoted. So ∀P ranges over families that no program could pick out. It also ranges over families that no type expression names, by the counting of {{allsets}}: the constant families alone are as many as the type sets, uncountably many, and there are countably many type expressions.
